### 3.1 ST-Link 烧录与开发板验证

使用 ST-Link/V2 连接开发板，在 Keil 中按 `F8` 下载程序。

下载成功时观察到：

```text
Erase Done
Programming Done
Verify OK
Flash Load finished
```

随后按开发板上的 `NRST` 复位键，程序重新从头运行。

实际现象：
- 蜂鸣器能够发出长—短—短提示音；
- LED 能够按照程序顺序闪烁；
- 将延时从 `250U` 改为 `500U` 后，LED 闪烁明显变慢；
- 断电后重新上电，Flash 中程序仍然存在并重新执行。

理解了：

```text
F7 → 编译、链接、生成固件
F8 → 将固件写入 STM32 Flash
NRST → 让 MCU 从启动流程重新运行程序
```

### 3.2 参数修改与硬件现象观察

完成了多组参数修改并在开发板上观察结果：

```c
current_led = 1U;
```

改为：

```c
current_led = 2U;
```

程序从 LED2 开始运行。

将：

```c
#define BEEP_MS 120U
```

改为：

```c
#define BEEP_MS 300U
```

蜂鸣器单次鸣叫时间变长。

将：

```c
delay_ms -= 20U;
```

改为：

```c
delay_ms += 20U;
```

LED 闪烁速度逐渐变慢。

注释：

```c
beep(BEEP_MS);
```

后，主循环中的规律蜂鸣消失。

由此进一步熟悉：

```text
修改代码
→ F7
→ F8
→ NRST / 重新上电
→ 观察硬件现象
```

### 3.4 报警系统模块化

新建：

```text
user/inc/alarm_system.h
user/src/alarm_system.c
```

头文件中声明：

```c
#ifndef ALARM_SYSTEM_H
#define ALARM_SYSTEM_H

#include <stdint.h>

void blink_led(uint8_t led_num, uint16_t times, uint32_t delay_ms);
void beep(uint32_t beep_ms);
void alarm_sys_func(void);

#endif
```

将 `blink_led()`、`beep()`、`alarm_sys_func()` 放入 `alarm_system.c`。

`main.c` 中只保留：

```c
#include "alarm_system.h"
```

并在主循环中调用：

```c
while (1)
{
    alarm_sys_func();
}
```

完成了从“所有功能集中在 `main.c`”到“按功能拆分模块”的基本过渡。

### 3.5 Include Path、Keil Group 与链接

将：

```text
user/src/alarm_system.c
```

加入 Keil 的 `user` Group，并保证：

```text
user/inc
```

位于 Include Paths 中。

理解：

```text
Include Paths
→ 让编译器找到 .h

Keil Group 中的 .c
→ 让源文件参与编译并生成 .o

链接器
→ 将不同 .o 中的函数调用与函数实现对应起来
```

如果头文件能找到，但 `.c` 没有加入工程，链接阶段可能出现：

```text
Undefined symbol
```

### 3.6 头文件保护与 `stdint.h`

学习：

```c
#ifndef ALARM_SYSTEM_H
#define ALARM_SYSTEM_H

...

#endif
```

其作用是防止同一个头文件在同一个 `.c` 文件的预处理过程中重复展开。

由于头文件使用：

```c
uint8_t
uint16_t
uint32_t
```

因此加入：

```c
#include <stdint.h>
```

使头文件本身具备所需类型定义。

### 3.7 三状态报警系统

定义：

```c
#define MODE_STANDBY 0U
#define MODE_RUN     1U
#define MODE_ALARM   2U
```

在 `alarm_sys_func()` 中使用：

```c
switch (mode)
```

实现：

```text
待机
→ LED 全灭、蜂鸣器关闭
→ 运行

运行
→ LED 依次闪烁
→ 报警

报警
→ LED 快速闪烁并蜂鸣
→ 待机
```

开发板实际运行结果正确。

### 3.8 `static` 局部变量

使用：

```c
static uint8_t mode = MODE_STANDBY;
```

理解了：
- `mode` 只在第一次初始化；
- 函数结束后仍保留当前值；
- 下一次进入 `alarm_sys_func()` 时继续使用上一状态。

普通局部变量：

```c
uint8_t led_num = 0U;
```

则用于当前一轮 LED 遍历，不需要跨函数调用保存。

### 3.9 STM32 启动流程

根据 README 学习了：

```text
上电 / NRST
→ startup_stm32h723xx.s
→ SystemInit()
→ main()
→ HAL_Init()
→ SystemClock_Config()
→ MX_GPIO_Init()
→ while(1)
→ alarm_sys_func()
```

初步理解：
- 启动文件负责最底层启动准备；
- 栈用于函数调用和局部数据等运行时管理；
- 中断向量表记录复位和中断处理入口；
- `HAL_Init()` 初始化 HAL 基础环境和 SysTick；
- `SystemClock_Config()` 配置系统时钟；
- `MX_GPIO_Init()` 配置 LED、蜂鸣器对应 GPIO。

### 3.10 CubeMX `USER CODE` 区域

学习了：

```c
/* USER CODE BEGIN ... */

/* USER CODE END ... */
```

理解：
- 对 C 编译器来说只是注释；
- CubeMX 会识别这些区域；
- 用户代码应尽量写在这些区域内；
- 写在区域外的手动代码在重新 Generate Code 时可能被覆盖。

同时形成习惯：

```text
CubeMX 自动生成文件
→ 少改

user/*.c
→ 放主要业务逻辑
```

### 3.11 `#define` 与 `const`

理解：

```c
#define LED_COUNT 4U
```

本质是预处理阶段的文本替换。

而：

```c
const uint8_t led_count = 4U;
```

是有明确类型的只读对象。

| 项目 | `#define` | `const` |
|---|---|---|
| 本质 | 文本替换 | 有类型的只读对象 |
| 阶段 | 预处理 | 编译 |
| 类型 | 无 | 有 |
| 分号 | 不需要 | 需要 |

### 3.12 函数参数值传递

普通函数调用时，实参的值会复制给形参。

例如：

```c
uint8_t a = 3U;
change(a);
```

函数：

```c
void change(uint8_t x)
{
    x = 10U;
}
```

执行后 `a` 仍为 `3U`，因为修改的是函数自己的局部变量 `x`。

### 3.13 `switch` 与 `if`

理解：

```text
固定几个状态值
→ switch

范围判断、复杂逻辑
→ if / else if / else
```

报警系统的 `0/1/2` 三种模式适合使用 `switch`。

### 3.14 固定宽度整数类型与 `U`

学习：

```text
uint8_t  → 8 位无符号整数，0~255
uint16_t → 16 位无符号整数，0~65535
uint32_t → 32 位无符号整数，范围更大
```

`1U`、`100U`、`300U` 中的 `U` 表示无符号整数字面量。

理解：

```text
.h 中的声明
→ 告诉编译器函数如何调用

.c 中的定义
→ 提供函数真正实现

.o

链接器

```

### 3.16 Keil 报错分层排查

| 现象 | 优先检查 |
|---|---|
| `file not found` | `.h`、Include Paths、文件名 |
| C 语法错误 | 分号、括号、语句结构 |
| `Undefined symbol` | `.c` 是否加入工程、函数是否定义 |
| `multiple definition` | 是否重复定义函数 |
| F8 下载失败 | ST-Link、供电、连接、下载配置 |
| F7/F8 成功但现象错误 | 程序逻辑、GPIO、接线、硬件 |

### 3.17 LED 控制调用链

结合工程理解：

```text
alarm_sys_func()
→ blink_led()
→ led_on()
→ HAL_GPIO_WritePin()
→ GPIO
→ 实际 LED
```

当前硬件映射：

```text
LED1 → PB3
LED2 → PB4
LED3 → PB5
LED4 → PB6
蜂鸣器 → PB0
```

进一步理解了“上层描述要做什么，底层负责具体操作硬件”的分层思想。

## 4. 核心概念

- STM32 程序烧录到 Flash 后，断电不会丢失；
- `NRST` 是复位，不是退出程序；
- STM32 主程序通常长期运行在 `while(1)`；
- `F7` 负责构建，`F8` 负责下载；
- `.h` 提供声明，`.c` 提供实现；
- Include Path 负责找到头文件，Group 中的 `.c` 负责参与构建；
- `USER CODE` 区域用于保护 CubeMX 工程中的用户代码；
- `#define` 是文本替换，`const` 是有类型的只读对象；
- 普通函数参数采用值传递；
- `static` 局部变量可以跨函数调用保存状态；
- `switch` 适合固定状态，`if` 适合范围判断；
- 软件可以按“业务逻辑 → 功能封装 → 硬件驱动 → HAL → GPIO”分层；
- 出现错误时应先区分编译、链接、下载和运行阶段。
