### 作业 3：封装流水灯

使用结构体保存一次闪烁的参数：

```c
typedef struct
{
    uint8_t led_num;
    uint16_t on_ms;
    uint16_t off_ms;
} blink_config;
```

实现内部函数：

```c
static void blink(blink_config config);
```

`blink()` 内部完成：

```text
检查 LED 编号
→ LED 点亮
→ 延时
→ LED 熄灭
→ 延时
```

同时将：

```c
led_on()
led_off()
blink()
```

都作为 `led.c` 内部函数处理，其中 `led_on()` 和 `led_off()` 使用 `static`，并从 `led.h` 中删除其公共声明。

最终模块关系为：

```text
main.c
   ↓
flow_led()          ← 公共接口
   ↓
blink()             ← led.c 内部函数
   ↓
led_on()/led_off()  ← led.c 内部函数
```

`led.h` 只保留公共流水灯函数，实现了基本的模块封装。

### 作业 4：远程流水状态机（选做）

使用枚举定义三种模式：

```c
typedef enum
{
    FLOW_SINGLE = 0,
    FLOW_PAIR,
    FLOW_ALL
} flow_mode;
```

定义当前状态：

```c
static flow_mode current_mode = FLOW_SINGLE;
```

使用全局变量：

```c
int signal = 0;
```

模拟外部遥控信号，并在 `led.c` 中通过：

```c
extern int signal;
```

读取该变量。

三种模式如下：

```text
signal = 0
→ FLOW_SINGLE
→ LED1 → LED2 → LED3 → LED4

signal = 1
→ FLOW_PAIR
→ 12 → 23 → 34

signal = 2
→ FLOW_ALL
→ 四颗 LED 同时亮灭
```

通过 `update_mode()` 根据 `signal` 更新 `current_mode`，再使用：

```c
switch (current_mode)
```

执行不同模式。

为了避免一整轮灯效执行完后才检查信号，在单灯和双灯模式的循环中增加状态检查，使程序大约每 500 ms 有机会重新判断一次模式，提高状态切换响应速度。

由于没有遥控器，本次通过手动修改 `signal = 0 / 1 / 2`、重新编译烧录的方式分别验证三种模式，均运行正常。

## 三、README 重点知识整理

### 1. `.h`、`.c` 与 `main.c`

- `.h`：声明模块对外提供的函数、类型和宏；
- `.c`：实现函数具体逻辑；
- `main.c`：调用各模块提供的公共接口。

基本原则：

```text
.h 负责“告诉别人能用什么”
.c 负责“具体怎么实现”
```

---

### 2. `static`

主要学习了三种用途：

- `static` 函数：只在当前 `.c` 文件中可见；
- `static` 全局变量：只在当前 `.c` 文件中可见；
- `static` 局部变量：函数结束后仍保留原来的值。

本次作业中主要使用第一种，用于隐藏：

```c
static void led_on(...);
static void led_off(...);
static void blink(...);
```

---

### 3. `extern`

表示变量或函数在其他文件中定义，本文件只进行声明。

例如：

```c
extern int signal;
```

表示 `signal` 真正定义在其他 `.c` 文件中。

不应在多个文件中重复定义同一个全局变量。

---

### 4. `register`

表示建议编译器将变量放入寄存器中以提高访问速度。

现代编译器通常会自动优化，因此实际代码中很少需要主动使用。

---

### 5. `const`

表示数据只读，不应该通过该变量名修改。

例如：

```c
const uint16_t delay_ms = 250U;
```

适合固定参数、配置数据和常量表。

---

### 6. `volatile`

表示变量可能被中断、硬件或其他异步过程修改，编译器不能假设它一直不变。

例如：

```c
volatile uint8_t button_pressed;
```

常用于：

- 中断标志位；
- 硬件寄存器；
- DMA 等异步数据。

---

### 7. `signed` 与 `unsigned`

- `signed`：可以表示正数、0 和负数；
- `unsigned`：只表示非负数。

例如：

```c
int16_t speed;
```

适合用正负值表示电机正反转；

```c
uint8_t led_num;
```

适合表示 LED 编号。

常量后面的 `U` 表示无符号整数字面量，例如：

```c
250U
4U
```

---

### 8. `sizeof`

用于获取变量或类型占用的字节数。

例如：

```c
sizeof(uint32_t)   // 通常为 4
```

也可以计算数组元素数量：

```c
sizeof(array) / sizeof(array[0])
```

---

### 9. `struct`

用于把多个相关数据组合成一个整体。

例如本次闪烁参数：

```c
typedef struct
{
    uint8_t led_num;
    uint16_t on_ms;
    uint16_t off_ms;
} blink_config;
```

访问成员使用：

```c
config.led_num
config.on_ms
```

---

### 10. `union`

联合体中的不同成员共用同一块内存。

例如：

```c
typedef union
{
    uint8_t a;
    uint16_t b;
    uint32_t c;
} test_union;
```

其大小通常由最大的成员决定。

与 `struct` 的区别：

```text
struct → 每个成员分别占空间
union  → 所有成员共用同一块空间
```

---

### 11. 宏函数与 `inline`

宏函数：

```c
#define IS_VALID_LED(id) ((id) < LED_COUNT)
```

本质是预处理阶段的文本替换。

`inline` 函数：

```c
static inline uint8_t is_valid(uint8_t id)
{
    return id < LED_COUNT;
}
```

是真正的函数，有参数和返回值类型检查。

---

### 12. 数组与 `const` 表

数组可以集中保存一组固定配置：

```c
const uint8_t led_list[] = {0U, 1U, 2U, 3U};
```

通过下标访问：

```c
led_list[0]
led_list[1]
```

数组下标从 0 开始。

配合：

```c
sizeof(led_list) / sizeof(led_list[0])
```

可以自动得到数组元素数量。

---

### 13. `enum`

用于给一组有限状态起有意义的名字。

例如：

```c
typedef enum
{
    FLOW_SINGLE,
    FLOW_PAIR,
    FLOW_ALL
} flow_mode;
```

默认从 0 开始依次递增。

相比直接使用数字，枚举能够提高代码可读性。

---

### 14. 状态机

状态机的核心是：

```text
状态 + 状态迁移
```

基本流程：

```text
读取输入
→ 更新当前状态
→ switch(state)
→ 执行当前状态对应动作
→ 下一轮继续判断
```

其中：

- `enum`：定义有哪些状态；
- `current_mode`：记录当前状态；
- `signal`：作为状态切换输入；
- `switch`：执行不同状态的行为。

进一步可以把状态机理解为：

```text
enter  → 刚进入状态时执行一次
run    → 状态持续期间反复执行
exit   → 离开状态前执行一次
switch → 切换到新状态
```

## 四、调试过程中遇到的问题

### 1. `blink()` 声明顺序问题

曾出现类似：

```text
static declaration of 'blink' follows non-static declaration
```

原因是 `flow_led()` 在编译器看到 `blink()` 的声明之前就调用了它。

解决方法是在前面增加函数声明：

```c
static void blink(blink_config config);
```

再在后面实现具体函数。

---

### 2. 两个 `blink()` 不能实现两灯同时亮

尝试：

```c
blink(config1);
blink(config2);
```

时发现两个函数是顺序执行的，因此效果是：

```text
LED1 完成亮灭
→ LED2 再完成亮灭
```

而不是两灯同时亮。

因此双灯模式改为：

```c
led_on(i);
led_on(i + 1U);
HAL_Delay(...);

led_off(i);
led_off(i + 1U);
HAL_Delay(...);
```

实现真正的同步亮灭。

---

### 3. `HAL_Delay()` 的阻塞问题

状态机中如果一次执行过长的 `HAL_Delay()`，程序就不能及时重新读取 `signal`。

本次通过缩短单次动作周期，并在单灯、双灯循环内部重新执行 `update_mode()`，把模式检查周期控制在约 500 ms。

后续如果需要更快、更实时的状态切换，可以继续学习：

```text
HAL_GetTick()
定时器
非阻塞状态机
```
