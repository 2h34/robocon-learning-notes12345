### 3.2 分支、合并与回退

创建 `feature-blink` 分支，在分支中修改代码后合并回 `main`：

```bash
git checkout -b feature-blink
git checkout main
git merge feature-blink
```

本次属于 Fast-forward 快进合并，即 `main` 直接移动到功能分支的最新提交，没有额外生成合并提交。

使用 Git Graph 查看分支和提交关系，并体验版本回退：

```bash
git reset --hard HEAD~1
```

三种回退模式区别：

| 模式 | 工作区修改 | 暂存状态 | 适用场景 |
|---|---|---|---|
| Soft | 保留 | 保留 | 修改提交信息、重新提交 |
| Mixed | 保留 | 取消暂存 | 重新整理提交内容 |
| Hard | 丢弃 | 恢复到目标提交 | 完全回到旧版本 |

操作中还遇到过未完成 Cherry-pick 的问题，使用：

```bash
git cherry-pick --abort
```

恢复仓库状态。

### 3.3 GitHub 远程仓库

创建个人公开仓库后，将本地仓库与远程仓库关联：

```bash
git remote add origin https://github.com/2h34/git-github-.git
git push -u origin main
```

之后在 GitHub 网页修改 `README.md`，再通过：

```bash
git pull
```

把远程更新同步到本地。

对应图形化流程为：

```text
源代码管理
→ 添加远程仓库
→ 推送
→ GitHub 网页提交
→ 拉取
```

### 3.6 编译产物

主要编译产物如下：

| 文件类型 | 作用 |
|---|---|
| `.o` | 单个源文件编译后的目标文件 |
| `.axf` | 链接后的可执行映像，包含调试信息 |
| `.hex` | 可写入单片机 Flash 的固件文件 |
| `.map` | 查看地址分配和空间占用 |
| `.d` | 记录源文件依赖关系 |

编译流程为：

```text
C 源代码
→ 预处理
→ 编译
→ 汇编
→ 链接
→ .axf / .hex
```

### 3.7 添加 `user` 组件

在 Keil 中新建 `user` Group，并添加：

```text
user/src/user_beep.c
```

在：

```text
Options for Target
→ C/C++
→ Include Paths
```

中加入：

```text
..\user\inc
```

然后在 `main.c` 中添加：

```c
#include "user_beep.h"
```

重新编译后结果正常，说明 `.c` 文件和头文件路径均配置成功。

### 3.8 编译错误与链接错误

临时移除：

```text
..\hardware\inc
```

出现：

```text
'buzzer.h' file not found
```

说明 `Include Paths` 负责让编译器找到 `.h` 头文件。

移除 `buzzer.c` 和 `led.c` 后，出现：

```text

```

说明 `.c` 文件负责提供函数实现。

| 情况 | 错误阶段 | 典型表现 |
|---|---|---|
| 缺少头文件路径 | 编译阶段 | `file not found` |
| 缺少源文件实现 | 链接阶段 | `Undefined symbol` |

## 4. 核心概念

- Git 负责记录版本，GitHub 负责保存和共享远程仓库；
- `add` 是暂存，`commit` 才会形成正式版本；
- 分支本质上是指向提交的指针；
- Fast-forward 合并不会额外产生合并提交；
- `reset --hard` 会同时恢复提交位置、暂存区和工作区；
- Push 是上传本地提交，Pull 是获取并合并远程更新；
- Keil 的 `F7` 会完成编译、链接和固件生成；
- Include Path 负责找到头文件，Group 中的 `.c` 文件负责提供函数实现；
- 修改源码后必须重新编译，下载后芯片才会运行新程序。
