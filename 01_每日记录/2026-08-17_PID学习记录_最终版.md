## 三、P：比例控制

### 3.1 基本公式

P，Proportional，比例控制：

\[
e = target-feedback
\]

\[
U_P=K_p e
\]

其中：

- `target`：目标状态；
- `feedback`：实际反馈状态；
- `error`：当前误差；
- \(K_p\)：比例增益；
- \(U_P\)：P 项产生的控制作用。

最核心的理解是：

> **P 根据当前误差的大小产生控制作用。**

在 \(K_p\) 固定的情况下：

\[
|e|\uparrow \Rightarrow |U_P|\uparrow
\]

误差越大，P 项作用越强；误差越小，P 项作用越弱。

### 3.2 PID 输出不是天然的 PWM

学习过程中一个重要问题是：

> 在位置 PID 中，`output` 是不是目标速度？

答案是：**可以是，但不是 PID 公式本身规定的。**

例如人为设计位置环为：

```text
目标位置
↓
位置 PID
↓
目标速度
```

此时：

```text
target   → 目标位置
feedback → 实际位置
error    → 位置误差
output   → 目标速度
```

所以一个位置 P 环可能写成：

\[
target\_speed=K_p(position\_error)
\]

如果位置单位是 `mm`，输出速度单位是 `mm/s`，则 \(K_p\) 的单位承担了两种物理量之间的转换。

因此：

> **PID 的 output 不是天然等于 PWM、速度、电流或转矩。它代表什么由控制环的设计决定。**

## 四、关于 Kp 与系统现象的重要边界

今天学习过程中出现过一个很重要的逻辑问题。

最开始尝试根据：

\[
U_P=K_p e
\]

直接判断：

```text
Kp 小 → 慢
Kp 大 → 超调
Kp 更大 → 振荡
```

后来发现这种表达不严谨。

从 P 公式本身能够直接推出的只有：

> 在当前误差 \(e\) 不变时，\(K_p\) 越大，P 输出绝对值越大。

但是“是否超调”“是否振荡”属于**完整闭环系统行为**，还取决于：

- 机械惯性；
- 阻尼；
- 电机动力学；
- 内部速度环；
- 延迟；
- 控制周期；
- 输出限幅；
- 负载；
- 机械弹性等。

例如，如果设计一个理想模型：

\[
\dot{x}=K_p(target-x)
\]

系统甚至可以单调逼近目标，并不必然超调。

所以以后分析 PID 时必须区分：

### 公式直接结论

\[
K_p\uparrow
\Rightarrow
同样error下|U_P|\uparrow
\]

### 特定实际系统中的常见工程趋势

在机械、电机、惯性、延迟等条件基本固定时：

```text
Kp 偏小
→ 控制作用通常偏弱
→ 响应通常较慢

适当增大 Kp
→ 响应通常更积极

Kp 过大
→ 某些实际系统中更容易产生超调、振荡等风险
```

后者不能当作纯公式必然结论。

这是今天非常重要的一次概念纠正。

## 五、P-only 与稳态误差

P 控制并不是任何情况下都一定存在稳态误差。

为了分析这个问题，今天明确使用了一个特定模型：

> 系统在目标状态下仍然需要一个非零控制输出才能维持状态。

例如升降机构需要持续提供向上的保持转矩，抵消重力。

假设保持目标状态所需控制量为：

\[
u_{hold}
\]

而纯 P：

\[
u=K_p e
\]

如果：

\[
e=0
\]

则：

\[
u=0
\]

无法提供所需要的保持作用。

为了产生：

\[
u=u_{hold}
\]

必须存在：

\[
e_{ss}=\frac{u_{hold}}{K_p}
\]

因此在这个条件下会产生稳态误差。

今天形成的准确理解是：

> **P 控制并不是天然一定存在稳态误差；当目标状态需要非零维持控制量，而系统仅依赖 P 项提供该控制量时，可能需要一个非零误差来维持输出。**

## 六、I：积分控制

I，Integral，积分控制。

连续形式：

\[
U_I=K_i\int e(t)\,dt
\]

离散形式：

\[
integral \leftarrow integral+error\cdot T_s
\]

然后：

\[
U_I=K_i\cdot integral
\]

其中 `integral` 不是 PID 输出，而是 PID 内部保存的**累计误差状态**。

### 6.1 I 关注什么

P 只看：

> 现在差多少？

I 则关注：

> 这个误差持续了多长时间？

例如一个很小的误差：

```text
e = 5
```

如果只存在一个很短时间，积分很小。

如果这个误差持续很长时间：

```text
5
5
5
5
5
...
```

则 `integral` 会不断累计。

因此 I 可以让：

> **长期存在的小误差逐渐产生越来越明显的控制作用。**

这也是 I 能够帮助消除稳态误差的根本原因。

### 6.2 error=0 时 integral 不会自动变成 0

假设之前：

```text
integral = 20
```

后来：

```text
error = 0
```

则：

```c
integral += error * Ts;
```

变成：

```text
integral = integral + 0
```

所以：

```text
integral 仍然 = 20
```

它只是**停止增加**，不会自动清零。

如果之后 `error` 变为负数，则 `integral` 才会逐渐减小。

因此 I 项具有“历史记忆”。

---

## 七、Integral Windup：积分饱和

如果执行器已经达到能力极限，例如：

```text
最大允许电流 = 10 A
```

但是 PID 数学计算仍然希望：

```text
output = 20 A
```

真实系统只能执行 10 A。

如果此时误差仍然存在：

\[
integral \leftarrow integral+errorT_s
\]

积分仍然会继续累计。

这就是 **Integral Windup，积分饱和/积分累积过度** 的基本问题。

其核心不是“output 大”，而是：

> **执行器已经不能继续增加实际控制作用，但 PID 内部积分仍然继续记账。**

结果是后续即使误差已经很小甚至改变方向，之前累计的大量积分仍然可能继续产生较强的 \(U_I\)，导致恢复慢、冲过目标等风险。

---

## 八、积分限幅与输出限幅

今天学习了两个基础保护：

```text
integral_limit
output_limit
```

二者作用完全不同。

### 8.1 Integral Limit

积分限幅限制：

```text
integral
```

例如：

```text
integral_limit = 50
```

则：

\[
-50\le integral\le50
\]

目的：

> 防止积分内部状态无限累计。

需要注意：

```text
integral_limit = 50
```

不意味着：

```text
Ui ≤ 50
```

因为：

\[
U_I=K_i\cdot integral
\]

如果：

\[
K_i=2
\]

即使：

\[
integral=50
\]

也有：

\[
U_I=100
\]

### 8.2 Output Limit

最终：

\[
output=U_P+U_I+U_D
\]

如果：

```text
output_limit = 100
```

则最终返回：

\[
-100\le output\le100
\]

例如：

```text
raw_output = 60   → output = 60
raw_output = 150  → output = 100
raw_output = -180 → output = -100
```

它限制的是：

> **最终向后级发送的控制指令。**

### 8.3 两种限幅的区别

```text
integral_limit
→ 限制 PID 内部历史状态

output_limit
→ 限制最终 PID 输出
```

因此两个限制不能互相替代。

## 九、D：微分控制

D，Derivative，微分控制。

连续形式：

\[
U_D=K_d\frac{de}{dt}
\]

离散形式：

\[
derivative=
\frac{error-last\_error}{T_s}
\]

然后：

\[
U_D=K_d\cdot derivative
\]

D 关注的是：

> **误差正在以多快的速度发生变化。**

可以形成一个基本直觉：

```text
P → 当前误差
I → 历史累计误差
D → 误差变化趋势
```

### 9.1 “提前刹车”直觉

假设：

```text
last_error = 50
error      = 30
```

误差正在下降，则：

\[
error-last\_error<0
\]

因此在当前符号约定下，D 项可能产生负方向作用。

这意味着：

> 系统正在快速接近目标时，D 可以开始减弱当前前进方向的控制作用。

因此常用“提前刹车”“增加阻尼”帮助建立直觉。

但需要注意：

> **D 并不数学上保证一定没有超调。**

---

## 十、D 为什么容易受到噪声影响

D：

\[
\frac{error-last\_error}{T_s}
\]

本质是比较两个相邻采样周期的差值。

编码器反馈中可能存在：

- 测量噪声；
- 量化误差；
- 低速跳变；
- 小幅快速抖动。

因为 D 对“变化量”敏感，小的快速变化也可能产生明显 D 输出。

并且：

\[
T_s\downarrow
\]

在相同误差变化量下：

\[
\left|\frac{\Delta e}{T_s}\right|\uparrow
\]

因此 D 对高频反馈变化尤其敏感。

在当天前半段理论学习时，这里暂时没有继续进入 D 滤波、Derivative on Measurement（对反馈量微分）等工程实现。

但在晚间作业与 Simulink 调参实践中，进一步实际观察了 **Derivative Kick（微分冲击）**，并把 D 从“误差微分”改成了“反馈微分”，完成了对照验证。D 滤波与更高级的微分算法仍留到后续真实电机阶段。

## 十一、完整 PID

完整连续 PID：

\[
u(t)
=
K_p e(t)
+
K_i\int e(t)dt
+
K_d\frac{de(t)}{dt}
\]

定义：

\[
U_P=K_p e
\]

\[
U_I=K_i\int e(t)dt
\]

\[
U_D=K_d\frac{de}{dt}
\]

因此：

\[
output=U_P+U_I+U_D
\]

今天建立的核心心智模型：

```text
P：当前
现在差多少？

I：过去
这个误差已经累计了多少？

D：趋势
这个误差现在变化得多快？
```

## 十二、Up、Ui、Ud 的构成

今天一个实际困难是：

> 已经大概理解 P/I/D 的概念，但对 `Up、Ui、Ud` 到底如何构成不够清楚。

最终明确为：

```text
error
↓
Kp × error
↓
Up
```

```text
历史 error
↓
Σ(error × Ts)
↓
integral
↓
Ki × integral
↓
Ui
```

```text
当前 error - 上一周期 error
↓
÷ Ts
↓
derivative
↓
Kd × derivative
↓
Ud
```

然后：

```text
output = Up + Ui + Ud
```

需要特别区分：

```text
integral ≠ Ui
derivative ≠ Ud
```

而是：

\[
U_I=K_i\cdot integral
\]

\[
U_D=K_d\cdot derivative
\]

## 十三、连续 PID → 离散 PID

MCU 并不是连续计算 PID，而是在一个个离散时刻进行计算。

使用：

\[
e[k]
\]

表示第 \(k\) 个控制周期的误差。

离散 PID：

\[
e[k]=target-feedback
\]

\[
integral[k]
=
integral[k-1]+e[k]T_s
\]

\[
derivative[k]
=
\frac{e[k]-e[k-1]}{T_s}
\]

\[
U_P[k]=K_p e[k]
\]

\[
U_I[k]=K_i integral[k]
\]

\[
U_D[k]=K_d derivative[k]
\]

最后：

\[
output[k]=U_P[k]+U_I[k]+U_D[k]
\]

## 十四、Ts：控制周期

\(T_s\) 可以理解为：

**Sampling Period / Control Period（采样周期 / 控制周期）**

例如：

```text
Ts = 0.01 s
```

表示：

> 每 10 ms 执行一次控制计算。

### 14.1 Ts 对 I 的作用

\[
integral += error\cdot T_s
\]

积分关心的是：

> 误差持续了多长时间。

如果错误地写成：

```c
integral += error;
```

那么程序累计的实际上是：

> PID 被调用了多少次。

例如：

```text
1 ms 调一次
```

会比：

```text
10 ms 调一次
```

在相同真实时间内累计更多次。

因此必须乘 \(T_s\)。

### 14.2 Ts 对 D 的作用

\[
derivative=
\frac{\Delta error}{T_s}
\]

因为 D 要表达：

> 单位时间内误差变化了多少。

因此必须除以 \(T_s\)。

### 14.3 Ts 不一定数学上必须恒定

最开始容易理解成：

> I、D 必须使用固定 Ts，否则就失去意义。

更准确的说法是：

> **I、D 必须使用与真实控制间隔一致的 Ts。**

如果每次周期不同，但程序知道真实：

\[
T_{s,k}
\]

仍然可以正确计算：

\[
integral += error\cdot T_{s,k}
\]

以及：

\[
derivative=
\frac{error-last\_error}{T_{s,k}}
\]

真正有问题的是：

```text
真实周期在变化
↓
程序却始终假设一个固定 Ts
↓
I 对累计时间估计错误
D 对变化速度估计错误
```

工程上通常让 PID 周期保持稳定，是因为：

- 实现更简单；
- 控制器行为更可预测；
- 参数更容易调；
- 系统动态更容易分析。

---

## 十五、控制周期还影响反馈的及时性

即使公式正确使用 \(T_s\)，控制周期本身仍然会影响系统表现。

例如：

```text
A：1 ms 更新一次
B：20 ms 更新一次
```

真实系统始终连续变化，但是控制器只在离散时刻读取反馈。

所以如果周期太长：

```text
系统已经发生变化
↓
控制器还没到下一次采样
↓
仍然不知道最新 feedback
↓
继续使用上一周期 output
↓
修正动作滞后
```

因此：

> 控制周期太慢时，不一定是 PID 数学公式算错，而是控制器获取反馈、修正系统状态不够及时。

目前对 \(T_s\) 的理解可以总结为：

```text
Ts 决定多久执行一次 PID

Ts 参与 I：
error × Ts

Ts 参与 D：
Δerror / Ts

Ts 影响反馈获取和控制修正的及时性
```

## 十六、PID 为什么需要跨周期状态

离散 PID 中：

\[
integral[k]
=
integral[k-1]+e[k]T_s
\]

所以 I 必须保存：

```text
integral
```

D：

\[
derivative=
\frac{error-last\_error}{T_s}
\]

所以 D 必须保存：

```text
last_error
```

因此最核心的跨周期状态是：

```text
integral
last_error
```

当前 `error` 每次可以通过：

```c
error = target - feedback;
```

重新计算，因此它不一定必须作为跨周期状态保存。

## 十七、PID 数据结构设计

今天没有直接获得现成结构体，而是自己先设计。

第一版提出：

```text
P
I
D
integral
last_error
```

之后明确：

保存的应该是 PID **增益参数**：

```text
Kp
Ki
Kd
```

而不是每周期计算结果 `Up / Ui / Ud`。

随后加入：

```text
integral_limit
output_limit
```

最终基础结构可以设计为：

```c
typedef struct
{
    double Kp;
    double Ki;
    double Kd;

    double integral;
    double last_error;

    double integral_limit;
    double output_limit;
} PID_t;
```

其中：

```text
Kp / Ki / Kd
integral_limit
output_limit
→ 配置参数

integral
last_error
→ 控制器内部历史状态
```

## 十八、PID_Init() 设计过程

最开始误把运行阶段的数据放到了初始化函数：

```c
void PID_Init(double error, double Ts);
```

后来发现：

```text
error
```

是每个周期都会变化的运行时数据，不属于初始化参数。

因此 `PID_Init()` 应该接受：

```text
PID 对象
Kp
Ki
Kd
integral_limit
output_limit
```

最终设计：

```c
void PID_Init(PID_t *pid,
              double Kp,
              double Ki,
              double Kd,
              double integral_limit,
              double output_limit);
```

函数内部还应该：

```c
pid->integral = 0;
pid->last_error = 0;
```

这里形成的重要接口设计原则：

> **初始化函数主要设置长期配置参数，并建立干净的初始运行状态。**

## 十九、PID_Calculate() 设计

第一版：

```c
double PID_Calculate(
    double target,
    double feedback,
    double Ts,
    PID_t pid
);
```

主要问题在：

```c
PID_t pid
```

这是结构体按值传递。

函数内部修改：

```text
integral
last_error
```

只会修改结构体副本。

函数返回以后：

```text
原 PID 对象的历史状态没有改变
```

于是 I 和 D 无法跨周期工作。

因此改成：

```c
double PID_Calculate(PID_t *pid,
                     double target,
                     double feedback,
                     double Ts);
```

这里使用：

```text
PID_t *pid
```

是因为函数必须修改原 PID 对象的：

```text
integral
last_error
```

---

## 二十、PID_Reset() 设计

一开始把 Reset 理解成：

> 重新设置新的 Kp、Ki、Kd，然后 integral、last_error 清零。

后来区分了参数配置和运行状态两个职责。

最终：

```c
void PID_Reset(PID_t *pid);
```

它主要：

```c
pid->integral = 0;
pid->last_error = 0;
```

但是：

```text
Kp
Ki
Kd
integral_limit
output_limit
```

保持不变。

因此三个基础接口的职责是：

```text
PID_Init()
→ 设置参数 + 初始化状态

PID_Calculate()
→ 周期计算 + 更新历史状态

PID_Reset()
→ 清空运行历史
→ 不改变 PID 参数
```

以后如果需要在线修改参数，可以再增加：

```c
PID_SetParams(...)
```

但今天暂时没有扩展。

---

## 二十一、PID_Calculate() 内部执行顺序

今天最终确定的逻辑顺序：

```text
1. error = target - feedback

2. integral += error * Ts

3. integral 限幅

4. derivative =
   (error - last_error) / Ts

5. 计算 Up / Ui / Ud

6. output = Up + Ui + Ud

7. output 限幅

8. last_error = error

9. return output
```

其中非常关键的是：

```c
pid->last_error = error;
```

必须放在使用旧 `last_error` 计算 D **之后**。

错误写法：

```c
pid->last_error = error;

derivative =
    (error - pid->last_error) / Ts;
```

此时：

\[
error-last\_error=0
\]

所以 D 永远无法得到正确变化率。

形成的重要程序思想：

> **历史状态必须先被本周期使用，再更新成下一周期需要的新历史状态。**

这个思路以后也会出现在：

- 编码器差分测速；
- 数字滤波；
- 离散状态估计等算法中。

## 二十二、自己编写 PID_Calculate() 时出现的问题

今天实际尝试写了第一版 PID 代码，整体流程已经正确，但出现了一些代码问题。

### 22.1 输出下限判断方向错误

写成类似：

```c
else if(output > -output_limit)
{
    output = -output_limit;
}
```

这会导致正常输出也可能被错误限制到负下限。

例如：

```text
output = 20
limit = 100
```

虽然：

```text
20 > 100 → false
```

但：

```text
20 > -100 → true
```

结果错误地变成：

```text
output = -100
```

正确的逻辑应该判断：

```text
output < -output_limit
```

这是当天代码中最重要的实际逻辑错误。

### 22.2 结构体成员访问

部分代码直接写了：

```c
integral += error * Ts;
```

但 `integral` 实际属于 PID 对象：

```c
pid->integral
```

因此需要明确区分局部变量和结构体成员。

### 22.3 pid / p 命名不一致

函数参数使用：

```c
PID_t *pid
```

但内部部分代码写成：

```c
p->Kp
```

属于机械输入错误，需要统一名称。

### 22.4 abs 与浮点数

对 `double` 不应该直接使用整数绝对值函数：

```c
abs()
```

浮点数应使用：

```c
fabs()
```

不过更简单的工程设计是规定：

```text
integral_limit > 0
output_limit > 0
```

然后直接比较：

```text
limit
-limit
```

无需每次求绝对值。

### 22.5 Ts = 0 风险

代码：

```c
derivative =
    (error - pid->last_error) / Ts;
```

如果：

```text
Ts = 0
```

会产生除零问题。

因此真正形成通用 PID 模块时，需要决定如何处理非法的 `Ts`。

今天只识别该风险，没有继续设计错误处理。

## 二十三、PID 输出的物理意义

这是今天非常重要的一部分。

`PID_Calculate()`：

```c
PID_Calculate(pid, target, feedback, Ts);
```

只是一个通用数学函数。

它本身：

```text
不知道 mm
不知道 rpm
不知道 A
不知道 PWM
```

我们在控制系统设计中规定：

```text
输入是什么
输出要用来干什么
```

之后 PID 参数再与这一物理关系匹配。

---

## 二十四、位置环

可以设计：

```text
target   → 目标位置
feedback → 实际位置
error    → 位置误差
```

位置 PID：

```text
位置误差
↓
PID
↓
target_speed
```

代码概念：

```c
target_speed =
    PID_Calculate(
        &position_pid,
        target_position,
        actual_position,
        Ts
    );
```

所以：

> **位置环回答：“为了消除当前位置误差，我现在希望系统运动多快？”**

---

## 二十五、速度环

速度环：

```text
target   → 目标速度
feedback → 实际速度
error    → 速度误差
```

速度 PID 可以输出：

```text
目标电流 / 目标转矩
```

例如：

```c
target_current =
    PID_Calculate(
        &speed_pid,
        target_speed,
        actual_speed,
        Ts
    );
```

所以：

> **速度环回答：“为了让实际速度跟上目标速度，我现在需要多大的转矩/电流？”**

---

## 二十六、电流环

电流环：

```text
target   → 目标电流
feedback → 实际电流
error    → 电流误差
```

电流 PID 输出：

```text
功率级控制量
```

可能继续对应：

- 电压指令；
- PWM；
- 调制量等。

具体实现属于后续电机驱动/FOC 内容，今天没有深入。

---

## 二十七、为什么同一个 PID_Calculate() 能用于不同环

今天最终形成的理解是：

> **`PID_Calculate()` 是通用数学函数，具体物理意义由所在控制环的输入量、输出用途以及与之匹配的 PID 参数共同决定。**

需要特别注意：

并不是：

> 函数根据传入的数据自动“判断”自己现在控制的是速度还是位置。

而是：

```text
我们先设计控制环
↓
规定 target / feedback
↓
规定 output 的用途
↓
选择匹配的 Kp / Ki / Kd
↓
PID_Calculate() 只完成数学运算
```

---

## 二十八、Kp / Ki / Kd 的参数作用

今天没有使用机械调参口诀，而是先从公式直接判断。

### Kp

\[
U_P=K_p e
\]

所以：

> \(K_p\) 决定当前误差对 output 的影响强度。

### Ki

\[
U_I=K_i integral
\]

所以：

> \(K_i\) 决定历史累计误差对 output 的影响强度。

工程上表现为 I 作用增强后，对持续稳态误差的修正更强。

### Kd

\[
U_D=K_d derivative
\]

所以：

> \(K_d\) 决定误差变化趋势对 output 的影响强度。

最终记忆：

```text
Kp
→ 当前误差的权重

Ki
→ 历史累计误差的权重

Kd
→ 误差变化趋势的权重
```

---

## 二十九、参数变化与实际系统现象

需要继续保持严格边界。

公式能够直接推出：

```text
Kp ↑ → P作用增强
Ki ↑ → I作用增强
Kd ↑ → D作用增强
```

在同一个真实系统、其他条件基本不变时，才可以讨论常见趋势：

```text
Kp 太小
→ 控制通常偏弱

Kp 增大
→ 通常响应更积极

Kp 过大
→ 某些系统中超调、振荡风险增加
```

```text
Ki 较小
→ 持续误差消除较慢

Ki 增大
→ 积分修正增强

Ki 过大
→ 积分累积过强、超调等风险增加
```

```text
Kd 增大
→ 对误差变化趋势作用增强

适当 D
→ 某些系统中可以增加阻尼

Kd 过大
→ 更容易受到噪声、量化抖动影响
```

这些都属于：

> **工程经验趋势，而不是 PID 公式单独保证的结果。**

---

## 三十、看到系统现象时的第一层判断

今天建立的基本排查思路：

如果系统：

```text
当前误差明显
但控制作用偏弱
```

首先关注 P。

如果：

```text
已经基本接近目标
但长期存在一个小误差
```

首先关注 I。

如果：

```text
接近目标过程中变化较快
需要关注接近趋势 / 阻尼
```

可以关注 D。

但实际调试不能做到：

```text
一个现象
=
唯一一个参数问题
```

因为真实系统还受到：

- 机械；
- 电机；
- 传感器；
- 延迟；
- 控制周期；
- 限幅；
- 负载等因素影响。

## 三十一、为什么不同控制环频率不同

典型层级：

\[
f_{current}>f_{speed}>f_{position}
\]

即：

```text
电流环最快
速度环其次
位置环较慢
```

其物理原因是：

```text
电流变化
↓
产生转矩
↓
产生角加速度
↓
速度发生变化
↓
速度积累
↓
位置发生变化
```

因此一般越靠近电机电磁过程的内环动态越快。

---

## 三十二、为什么内环通常需要比外环快

串级结构：

```text
位置环
↓
给速度环目标

速度环
↓
给电流环目标

电流环
↓
驱动电机
```

外环希望：

> 自己给出的目标能够被内环比较快地跟踪。

因此：

> **内环通常需要具有比外环更快的动态响应和更新频率。**

但今天还专门纠正了一个容易形成的错误模型：

不是：

```text
外环执行一次
↓
等内环完全完成
↓
外环再执行
```

而是：

> **各环都持续周期运行，只是内环周期更短。**

---

## 三十三、时间尺度分离

例如：

```text
位置环：10 ms
速度环：1 ms
```

`t=0`：

```text
位置环计算：
target_speed = 100 rpm
```

之后：

```text
t=1 ms 速度环运行
t=2 ms 速度环运行
t=3 ms 速度环运行
...
```

在位置环下一次执行之前：

```text
target_speed
```

继续保持上一次值。

但是速度环反馈：

```text
actual_speed
```

一直在变化。

所以：

\[
speed\_error
=
target\_speed-actual\_speed
\]

也一直在变化。

因此：

> **外环 target 暂时不变，不代表内环 error 和 output 不变。**

---

## 三十四、串级 PID

串级 PID 最核心关系：

> **上一层 PID 的 output 成为下一层 PID 的 target。**

完整三环：

```text
目标位置
↓
位置 PID
↓
目标速度
↓
速度 PID
↓
目标电流 / 目标转矩
↓
电流 PID
↓
功率级控制量
↓
电机
```

---

## 三十五、位置环 → 速度环

例如：

```text
目标位置 = 500 mm
实际位置 = 300 mm
```

位置环：

```text
位置误差
↓
position PID
↓
target_speed = 200 mm/s
```

如果当前：

```text
actual_speed = 120 mm/s
```

速度环处理：

\[
e_{speed}
=
target\_speed-actual\_speed
\]

这里非常重要：

> **速度 PID 不直接处理位置误差。**

位置误差已经被位置 PID 转换成了：

```text
target_speed
```

---

## 三十六、速度环 → 电流环

速度 PID 进一步产生：

```text
target_current
```

例如：

```text
target_current = 3 A
actual_current = 2 A
```

则电流环只处理：

\[
e_{current}
=
target\_current-actual\_current
\]

它并不需要直接处理位置误差、速度误差。

每一环各自解决自己的跟踪问题。

---

## 三十七、串级 PID 的职责分工

可以形成下面的直觉：

```text
位置环：
我还差多远？
↓
应该运动多快？

速度环：
我距离目标速度还差多少？
↓
应该产生多大的转矩/电流？

电流环：
当前电流距离目标电流还差多少？
↓
功率级应该如何控制？
```

因此串级 PID：

> 不是一个 PID 同时处理多个误差，而是多个相对独立的 PID 控制器通过目标传递连接起来。

工程中可能有：

```c
PID_t position_pid;
PID_t speed_pid;
PID_t current_pid;
```

它们使用同一个：

```c
PID_Calculate()
```

但拥有独立的：

```text
Kp
Ki
Kd
integral
last_error
limit
控制周期
```

---

## 三十八、串级控制中的动态过程

原本：

```text
target_speed = 200
actual_speed = 180
```

速度误差：

\[
e_{speed}=20
\]

后来由于机器人已经靠近目标位置，位置环把：

```text
target_speed:
200 → 100
```

但真实速度此刻仍然接近：

```text
actual_speed = 180
```

于是：

\[
e_{speed}=100-180=-80
\]

速度误差变成负值。

在当前符号约定下：

> 速度环会开始产生让实际速度下降的控制作用。

因此：

```text
接近目标位置
↓
position_error 变小
↓
position PID 降低 target_speed
↓
speed target 下降
↓
实际速度暂时仍较高
↓
speed_error 可能变负
↓
speed PID 开始要求减速
```

这解释了位置环和速度环如何协同工作。

---

## 三十九、串级关系不等于固定的软件执行顺序

串级关系：

```text
position output
→ speed target

speed output
→ current target
```

描述的是：

> **数据与控制目标关系。**

并不要求程序必须永远：

```text
position PID
↓
speed PID
↓
current PID
↓
三个一起等待
```

实际程序可以让不同环按照不同周期调度。

例如：

```text
位置环：10 ms
速度环：2 ms
电流环：1 ms
```

这属于软件调度实现。

串级 PID 本身并不规定一定使用：

- Timer；
- FreeRTOS；
- 中断；
- 主循环。

这些是后续工程实现选择。

## 四十一、限幅的物理意义跟随 PID 输出

例如速度 PID 被设计成：

```text
output = target_current
```

```text

```

\[
-10A
\le
target\_current
\le
10A


则 `output_limit` 限制的是目标速度。

## 四十二、今天学习过程中出现的主要问题与纠正

### 问题 1：从 Kp 直接判断超调和振荡

最初容易把：

```text
Kp 大
```

直接等同于：

```text
超调 / 振荡
```

纠正后：

> P 公式只能直接确定 P 输出强弱，完整系统现象必须结合被控对象动力学判断。

这是今天最重要的理论边界纠正之一。

### 问题 2：把 integral 当成 Ui

后来明确：

```text
integral
```

只是累计误差状态。

真正：

\[
U_I=K_i integral
\]

同理：

```text
derivative ≠ Ud
```

而：

\[
U_D=K_d derivative
\]

### 问题 3：认为 Ts 必须永远固定

纠正为：

> PID 需要使用正确的真实时间间隔；工程上通常进一步把周期设计得稳定。

因此固定周期是常见优良工程实现，而不是数学意义上唯一可能形式。

### 问题 4：PID_Init() 与 PID_Calculate() 职责混淆

最开始：

```text
PID_Init(error, Ts)
```

把运行数据放进了初始化阶段。

纠正后：

```text
Init → 配置长期参数
Calculate → 处理实时 target / feedback / Ts
```

### 问题 5：结构体按值传递

最开始：

```c
PID_Calculate(..., PID_t pid)
```

会导致历史状态只在副本中更新。

纠正为：


## 四十四、晚间作业：增量式 PID 离散方程推导

晚间作业第 1 题要求推导增量式 PID 的离散输出方程。

位置式离散 PID 写为：

\[
u[k]
=
K_p e[k]
+
K_i\sum_{j=0}^{k} e[j]T_s
+
K_d\frac{e[k]-e[k-1]}{T_s}
\]

上一周期：

\[
u[k-1]
=
K_p e[k-1]
+
K_i\sum_{j=0}^{k-1} e[j]T_s
+
K_d\frac{e[k-1]-e[k-2]}{T_s}
\]

定义输出增量：

\[
\Delta u[k]=u[k]-u[k-1]
\]

逐项相减后：

### P 项

\[
\Delta U_P
=
K_p(e[k]-e[k-1])
\]

### I 项

两次累计和大部分完全相消，只剩第 \(k\) 项：

\[
\Delta U_I
=
K_iT_se[k]
\]

### D 项

\[
\Delta U_D
=
\frac{K_d}{T_s}
\left(e[k]-2e[k-1]+e[k-2]\right)
\]

因此最终得到：

\[
\boxed{
\Delta u[k]
=
K_p(e[k]-e[k-1])
+
K_iT_se[k]
+
\frac{K_d}{T_s}
\left(e[k]-2e[k-1]+e[k-2]\right)
}
\]

实际输出通过：

\[
\boxed{u[k]=u[k-1]+\Delta u[k]}
\]

递推得到。

有些教材会把 \(T_s\) 吸收到离散后的 \(K_i\)、\(K_d\) 中，因此公式外观可能没有显式的 \(T_s\)。本次学习统一保留 \(T_s\)，便于和前面的离散 PID 知识对应。

## 四十五、位置式 PID 与增量式 PID 对比

本次作业中进一步明确：

- **位置式 PID**：每个周期直接计算当前完整输出 \(u[k]\)；
- **增量式 PID**：每个周期只计算输出变化量 \(\Delta u[k]\)，再通过上一周期输出得到新的 \(u[k]\)。

核心区别：

| 项目 | 位置式 PID | 增量式 PID |
|---|---|---|
| 每周期计算对象 | 当前完整输出 \(u[k]\) | 输出增量 \(\Delta u[k]\) |
| 积分表达 | 显式出现累计误差 | 当前增量公式中累计和相消 |
| 历史作用 | 直接保存在积分状态中 | 也包含在上一周期输出 \(u[k-1]\) 中 |
| 使用直觉 | “现在应该输出多少” | “现在应该比上一次多/少输出多少” |

需要避免一个错误理解：

> **增量式 PID 并不是没有积分记忆。**

虽然 \(\Delta u[k]\) 的公式中不再显式出现 \(\sum e\)，但历史积分效果已经包含在不断递推形成的 \(u[k-1]\) 中。

## 四十九、Simulink 手工搭建增量式 PID

第 7 题为选做题，但本次不仅完成了模型搭建，还进行了较完整的调参与工程现象验证。

### 49.1 误差历史链

利用两个 `Unit Delay (1/z)` 保存：

```text
e[k] → 1/z → e[k-1] → 1/z → e[k-2]
```

统一设置：

```text
Initial condition = 0
Sample time = 0.01
```

即：

\[
T_s=0.01s
\]

### 49.2 P 支路

通过 Sum 计算：

\[
e[k]-e[k-1]
\]

再经过 Gain：

\[
K_p(e[k]-e[k-1])
\]

### 49.3 I 支路

直接使用当前误差：

\[
K_iT_se[k]
\]

因此只需要一个 `Gain = Ki*Ts`。

### 49.4 D 支路

先计算：

\[
e[k]-e[k-1]
\]

与：

\[
e[k-1]-e[k-2]
\]

再相减：

\[
e[k]-2e[k-1]+e[k-2]
\]

最后经过：

```text
Gain = Kd/Ts
```

### 49.5 输出递推

三路相加得到：

\[
\Delta u[k]
\]

再通过新的 `Unit Delay` 保存上一周期输出：

\[
u[k]=u[k-1]+\Delta u[k]
\]

这一部分让增量式 PID 的“每次只算变化量”真正落实到 Simulink 信号链中。

## 五十、P-only / I-only / D-only 基础验证

在闭环电机模型加入之前，先单独验证了三条支路是否按公式工作。

### 50.1 P-only

参数：

```matlab
Kp = 1;
Ki = 0;
Kd = 0;
Ts = 0.01;
```

输入误差 Step：

```text
0 → 1，发生在 t = 1 s
```

理论上：

\[
\Delta u=e[k]-e[k-1]
\]

只在阶跃瞬间出现一次 \(\Delta u=1\)，之后 \(\Delta u=0\)，因此最终：

```text
u：0 → 1，并保持在 1
```

Scope 结果与理论一致。

### 50.2 I-only

参数：

```matlab
Kp = 0;
Ki = 1;
Kd = 0;
Ts = 0.01;
```

误差变成 1 后：

\[
\Delta u_I=1\times0.01\times1=0.01
\]

所以每个周期输出增加 0.01，Scope 中表现为持续上升的直线。

### 50.3 D-only

参数：

```matlab
Kp = 0;
Ki = 0;
Kd = 0.01;
Ts = 0.01;
```

在 Step 瞬间形成一个约一个采样周期宽度的脉冲，随后回到 0。

该现象验证了：

> D 只对变化产生作用，恒定误差下不会持续输出。

## 五十五、Derivative Kick：目标阶跃导致的微分冲击

在误差微分实现中：

\[
D=K_d\frac{de}{dt}
\]

而：

\[
e=r-y
\]

所以：

\[
\frac{de}{dt}=\frac{dr}{dt}-\frac{dy}{dt}
\]

当目标值在 \(t=1s\) 从 0 突然跳到 1，而实际值 \(y\) 还来不及变化时，误差也会瞬间跳变。

在：

```matlab
Kp = 2;
Ki = 5;
Kd = 0.1;
Ts = 0.01;
```

下：

\[
\Delta U_P=2
\]

\[
\Delta U_I=5\times0.01=0.05
\]

\[
\Delta U_D=\frac{0.1}{0.01}\times1=10
\]

第一拍控制输出约：

\[
u\approx12.05
\]

Scope 中确实出现约 12 的尖峰。

之后进一步自行调整到：

```matlab
Kp = 2.9;
Ki = 5;
Kd = 0.2;
Ts = 0.01;
```

`target / actual` 曲线已经非常漂亮，但 \(u\) 的阶跃尖峰达到约：

\[
2.9+0.05+20\approx22.95
\]

Scope 实际约为 23。

这次实验形成了一个非常重要的工程判断：

> **响应曲线漂亮，不代表控制器输出一定合理。**

---

## 五十六、把 D 从误差微分改成反馈微分

为了减小目标阶跃引起的 Derivative Kick，进一步学习了 **Derivative on Measurement（对反馈量微分）**。

原来 D 看的是：

\[
\frac{de}{dt}
\]

而反馈微分改为只看实际反馈变化：

\[
-K_d\frac{dy}{dt}
\]

其中负号表示：实际反馈正在快速上升时，D 提供反向“刹车”作用。

需要特别注意：当天使用的是**增量式 PID**，因此严格对应到当前模型，新的 D 增量支路写成：

\[
\boxed{
\Delta U_D
=
-\frac{K_d}{T_s}
\left(y[k]-2y[k-1]+y[k-2]\right)
}
\]

因此在 Simulink 中重新建立：

```text
y[k] → 1/z → y[k-1] → 1/z → y[k-2]
```

并计算：

\[
y[k]-2y[k-1]+y[k-2]
\]

最后经过：

```text
Gain = -Kd/Ts
```

这个过程中还纠正了一个表达边界：

> \(-K_d(y[k]-y[k-1])/T_s\) 可以帮助理解“当前 D 作用”的机制，但如果严格对应当前的**增量式 PID 输出方程**，需要使用二阶差分形式。不能把位置式 D 项直接当成增量式 D 增量。

## 五十七、误差微分与反馈微分的实际 A/B 对照

保持：

## 五十九、加入 Saturation 后观察 Integral Windup

为了进一步模拟真实驱动器能力有限的情况，在 PID 输出和电机模型之间加入：

```text
Saturation
Upper limit = 1
Lower limit = -1
```

此时区分：

```text
u_PID
→ PID 内部想输出多少

u_act
→ 真正经过执行器限幅后送给电机多少
```

目标设为：

\[
target=2
\]

但执行器最大只能：

\[
u_{act}=1
\]

由于教学电机模型稳态增益约为 1，因此 actual 最多只能接近 1，长期误差约为：

\[
e\approx1
\]

而积分仍然继续累计。

当前：

\[
K_i=4,\qquad T_s=0.01
\]

所以稳态附近每个周期积分贡献约：

\[
\Delta U_I=4\times0.01\times1=0.04
\]

每秒 100 个周期，PID 内部输出大约每秒继续增加 4。

实际 Scope 中，PID 内部 \(u\) 从几开始一路增长，到 10 s 已经超过 40，出现明显的 Windup。

这次仿真把此前理论上的 Integral Windup 真正验证成了可见现象：

> **执行器已经到能力极限，继续增加控制命令没有实际效果，但积分仍然因为误差存在而不断累积。**

本次到这里停止深入，没有继续实现完整 Anti-Windup。

当前只需要掌握常见解决方向：

- integral clamp；
- 执行器饱和时有条件停止积分；
- 更完整的 Anti-Windup 算法以后真实电机阶段再学。

## 六十三、今天最值得记住的几点

1. **PID output 没有固定物理意义，必须由控制环设计决定。**
2. **P 看当前误差，I 看历史累计，D 看变化趋势。**
3. **位置式 PID 算“当前完整输出”，增量式 PID 算“本周期输出变化量”。**
4. **增量式 PID 没有显式累计和，不代表没有积分记忆；历史作用被包含在上一周期输出中。**
5. **离散控制必须正确处理时间：I 乘 \(T_s\)，D 除 \(T_s\)。**
6. **同样误差下增大 \(K_p\) 只必然意味着 P 输出更强，不能脱离对象直接断言一定超调或振荡。**
7. **位置环 output → 速度环 target，速度环 output → 电流环 target。**
8. **只看 target / actual 曲线漂亮不够，还必须检查 PID 输出 \(u\) 是否合理。**
9. **误差微分会同时响应 target 与 feedback 的变化，因此设定值阶跃可能造成 Derivative Kick。**
10. **反馈微分让 D 只关注被控对象实际变化趋势，可以显著降低目标突变带来的控制冲击。**
11. **在增量式 PID 中，反馈微分 D 应严格使用反馈量的二阶差分形式，而不是直接把位置式 D 公式搬过来。**
12. **执行器饱和时，PID 内部继续积分会产生 Windup。**
13. **实际 PID 整定是在响应速度、稳态误差、超调、稳定时间、控制输出代价之间做权衡。**
14. **调出一组参数后还要换工况验证，不能只对一张曲线“过拟合”。**
15. **仿真中得到的参数只能说明当前模型表现良好，不能直接复制到真实电机。**
