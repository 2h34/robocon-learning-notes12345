# 二、DJI 电机工程化主线

## 1. 多电机控制结构确认

一开始重点检查了“单电机程序是否已经真正扩展成多电机结构”。

现有结构核心为：

```text
DJI_motor_t dji_motor[4]
```

每台电机拥有独立的：

```text
mode / mode_set
rpm / target_rpm
position / target_position
current / current_cmd
speed_pid
position_pid
encoder_total
feedback_valid
Zero 相关状态
```

### CAN ID → 电机对象映射

反馈帧 ID 为：

```text
0x201 → Motor 1
0x202 → Motor 2
0x203 → Motor 3
0x204 → Motor 4
```

程序中通过：

```c
motor_id = StdId - 0x200;
motor = &dji_motor[motor_id - 1];
```

完成 CAN ID 到数组对象的映射。

最终明确：

> 多台电机是“共享算法、独立状态”。

即：

```text
同一个 SpeedMode / PositionMode 函数
        ↓
作用于不同 DJI_motor_t 对象
        ↓
PID 历史状态、目标值、反馈值彼此独立
```

### 多电机统一 CAN 控制帧

四台电机的 `current_cmd` 最后统一打包进 `0x200` 控制帧：

```text
Byte 0~1 → Motor 1
Byte 2~3 → Motor 2
Byte 4~5 → Motor 3
Byte 6~7 → Motor 4
```

因此需要区分：

```text
控制计算：四台独立
CAN 发送：统一打包
```

这一部分已经通过现有代码确认，不再重复重构。

## 2. `feedback_valid` 为什么不等于“在线”

原程序中：

```c
motor->feedback_valid = 1;
```

只要曾经收到过一次反馈，就会一直保持为 1。

这只能表示：

> “从初始化以来，这台电机至少收到过一次合法反馈。”

但不能表示：

> “这台电机此刻仍然在线。”

### 正确的在线监控思路

在 CAN 接收函数中记录最近一次收到反馈的时间：

```text
收到反馈
↓
更新 last_rx_tick
```

然后在周期性 Monitor / 状态机中：

```text
now = HAL_GetTick()
↓
now - last_rx_tick
↓
超过 timeout
↓
offline / fault
```

学习中明确了一个关键点：

> 监控函数不能放在 `DJI_motor_Receive()` 里负责“掉线判断”。

因为真的掉线后：

```text
没有 CAN 帧
→ DJI_motor_Receive() 根本不会再运行
```

因此在线监控必须由**周期任务/状态机主动检查**。

### 掉线后的安全处理思路

不能只做：

```c
online = 0;
```

还应考虑：

```text
进入 fault / offline
↓
请求 Disable
↓
PID Reset
↓
current_cmd = 0
```

本次没有要求实际改入工程，只掌握设计思路。

### 掉线后重新上线是否自动恢复？

讨论后得到的合理策略是：

```text
掉线
→ 进入保护状态（如 DJ_Disable）

通信恢复
→ 只恢复“在线”状态
→ 不自动恢复原运动

真正恢复运动
→ 由上层重新发出模式/目标命令
```

原因：

> 通信恢复 ≠ 重新获得运动授权。

这比“掉线后自动接着跑原目标”更安全、更容易管理。

## 3. 堵转检测思路

最初容易产生的误区：

```text
rpm ≈ 0
→ 堵转
```

这是不成立的。

例如位置模式中，电机已经接近目标：

```text
position ≈ target_position
rpm ≈ 0
```

这是完全正常的。

### 堵转判断应综合多个条件

例如 RPM 模式中：

```text
target_rpm 很大
actual_rpm ≈ 0
current / current_cmd 较大
持续一段时间
```

才比较像真实堵转。

因此堵转检测应考虑：

- 当前 mode；
- 是否存在明确运动需求；
- target 与 feedback 的差异；
- 实际速度 / 编码器变化；
- 电流或输出大小；
- 持续时间。

### Zero 模式是特殊情况

Zero 的目的本身就是：

```text
主动运动到机械限位
↓
速度逐渐接近 0
↓
确认连续静止
↓
判定到达机械零点
```

因此：

> Zero 的机械限位确认不能被普通堵转逻辑误判。

最终结论：

```text
普通模式堵转 → Monitor 判断
Zero 模式 → 优先交给 Zero 自己的机械限位确认逻辑
```

本次同样只要求掌握工程思路，不强制加入现有代码。

## 4. 转子侧与输出轴侧坐标

学习中进一步明确：

- 转子速度 / 转子位置；
- 减速器输出轴速度 / 输出轴位置；
- PID target 与 feedback 必须使用同一坐标定义。

M2006 P36 的减速比为：

```text
36 : 1
```

讨论中没有强制规定“必须在哪个函数换算”，而是明确了更重要的原则：

> 坐标系必须统一，调试、限幅、PID 参数和 Debug 观察都必须基于同一套定义。

如果把 `target_rpm` 和 `rpm` 都统一理解为输出轴速度，那么 PID 数值会随坐标尺度变化而重新调整，这本身没有问题。

本次最后没有继续纠结具体实现位置，重点是理解坐标边界。

## 5. 模块 API 与 `static`

现有 `dji_motor.h` 暴露了较多内部辅助函数，例如：

```text
AngleCalculate
CurrentTransmit
SpeedMode
PositionMode
CurrentMode
ZeroMode
ClampPeak
SwitchMode
```

讨论后形成的模块化原则：

> `.h` 不应该表达“模块内部有哪些函数”，而应该表达“其他模块允许对这个模块做什么”。

### 建议保留的公共接口

例如：

```text
DJI_motor_init()
DJI_motor_Receive()
DJI_motor_Func()
DJI_motor_SetMode()
DJI_motor_SetSpeed()
DJI_motor_SetPosition()
DJI_motor_SetCurrent()
DJI_motor_SetZero()
```

### 更适合作为内部函数的内容

例如：

```c
static void DJmotor_SpeedMode(...);
static void DJmotor_PositionMode(...);
static void DJI_motor_AngleCalculate(...);
static void DJI_motor_CurrentTransmit(...);
```

对于文件作用域函数：

```c
static void func(...)
```

表示：

> 该函数只在当前 `.c` 文件内部可见。

这样可以防止上层绕过：

```text
SetMode
→ mode_set
→ SwitchMode
→ PID Reset
```

等设计好的控制流程。

### 关于结构体是否完全隐藏

当前学习/调试阶段不建议过度封装。

可以暂时允许：

```text
DJI_motor_t 类型公开
数组也可用于 Debug / 状态读取
```

但正式业务代码应尽量通过：

```text
SetMode / SetSpeed / SetPosition ...
```

修改控制状态，而不是直接写：

```c
dji_motor[0].mode = ...;
dji_motor[0].current_cmd = ...;
```

当前阶段目标是：

> 先隐藏内部函数，不强制把整个电机对象完全隐藏。

## 6. DJI 完整数据流梳理

最终把一帧反馈到下一帧控制命令完整串了一遍。

### 反馈路径

```text
C610 CAN 反馈
↓
CAN Callback
↓
DJI_motor_Receive()
↓
StdId → motor 对象
↓
encoder / rpm / current
↓
多圈位置计算
```

Receive 只负责：

> 更新“现在实际发生了什么”。

### 上层状态机

状态机只负责表达：

> “机器人希望电机干什么”。

例如：

```text
SetPosition
SetSpeed
SetCurrent
SetMode
```

### 周期控制

```text
DJI_motor_Func()
↓
SwitchMode
↓
根据 mode 调用 Position / RPM / Current / Zero
↓
PID
↓
current_cmd
↓
统一 CAN 0x200 发送
```

最后形成三层职责：

```text
CAN Receive：更新实际状态
State Machine：给出控制目标
Periodic Control：根据目标和反馈计算输出
```

需要牢记：

> `SetPosition()` 调用结束 ≠ 电机已经到达目标位置。

函数调用边界和物理任务完成边界必须区分。

# 四、PID 调参扩展学习

DJI 主线完成后，补充学习了“如何选 Kp / Ki / Kd”，并重点实践了串级 PID 调参。

---

## 1. 单环网页调参：P / PI / PID 作用重新建立直觉

使用网页模拟器进行单环练习。

### 纯 P

观察到：

```text
Kp 增大
→ 响应更快
→ 稳态误差减小
```

但纯 P 仍可能存在明显稳态误差。

### 加 I

加入积分后：

```text
稳态误差明显减小/消失
```

同时也观察到：

```text
Ki 太大
→ 超调增大
→ 稳定时间变长
→ 积分历史导致“继续推”
```

### 加 D

D 可以提供阻尼，但不是越大越好。

随后 Simulink 中又进一步看到：

```text
Kd 较大
→ 高频抖振
```

由此真正理解：

> D 不是“第三个必须调的旋钮”，而是对变化率非常敏感的阻尼项。

如果 PI 已经满足需求，完全可以不使用 D。

# 五、Simulink 串级 PID 建模实践

## 1. 为什么自己搭模型

最终没有继续使用复杂 FOC 网页，而是在 Simulink 中搭建一个与真实 `dji_motor.c` 结构高度对应的简化模型。

核心结构：

```text
target_position
      ↓
Position PID
      ↓
target_rpm
      ↓
Speed PID
      ↓
current
      ↓
M2006 简化模型
      ↓
rpm
      ↓
position
```

### 使用的 M2006 参数

来源：RoboMaster M2006 P36 使用说明。

主要采用：

```text
转矩常数 Kt = 0.18 N·m/A
转速转矩梯度 = 110 rpm/(N·m)
机械时间常数 = 52.78 ms
减速比 = 36:1
```

构造第一版简化机械模型：

```text
电流 I
↓ ×0.18
转矩 T
↓
110 / (0.05278 s + 1)
↓
rpm
```

这只是用于调参训练的**简化模型**，没有模拟 C610 内部 FOC / 电流环动态，因此不能理解成高保真数字孪生。

---

## 2. 建模过程中遇到的问题与纠正

### 问题 1：Scope 没有看到曲线

最初：

```text
Step time = 1 s
Stop time = 1 s
```

等于：

```text
刚发生阶跃
→ 仿真立即结束
```

修正：

```text
Stop time > Step time
```

例如：

```text
Step = 1 s
Stop = 3 s
```

### 问题 2：仿真一直显示“正在运行”

曾尝试检查求解器、固定步长等设置。

最后重启 Simulink 后恢复正常。

经验：

> 简单模型长时间不结束时，先判断是否是 Simulink 运行状态/求解器异常，不要立刻怀疑 PID 本身。

### 问题 3：纯 P `Kp=0.05` 居然接近 100 rpm

这一步是今天很典型的调试问题。

按闭环理论，`Kp=0.05` 不应接近 100 rpm。

重新检查模型后发现：

> 速度负反馈线实际上没有真正接到 Sum 的负端。

当时系统实际处于开环：

```text
100 rpm Step
↓
Kp = 0.05
↓
5 A
↓ ×0.18
0.9 N·m
↓ ×110
≈ 99 rpm
```

所以 Scope 接近 99 rpm 反而证明了“反馈没接上”。

修正反馈后：

```text
Kp=0.05 → 稳态约 50 rpm
```

与理论结果一致。

这一过程强化了一个调试经验：

> 曲线异常时，不要先调 PID；先检查闭环结构、信号方向和单位。

# 六、速度内环调参

## 1. 纯 P 调参

速度目标先设置为 100 rpm。

观察：

```text
Kp = 0.05 → 稳态约 50 rpm
Kp = 0.10 → 稳态约 66 rpm
```

进一步理解：

> 纯 P 下，Kp 越大稳态误差越小，但不能靠无限增加 Kp 解决所有问题。

---

## 2. 电流限幅对调参的影响

初始设置：

```text
current saturation = ±10 A
目标速度 = 100 rpm
```

当：

```text
Kp = 0.1
初始误差 = 100 rpm
```

P 项立即要求：

```text
0.1 × 100 = 10 A
```

刚好顶到电流限幅。

进一步增加 Kp 后：

```text
PID 想输出 >10 A
↓
仍然只能实际输出 10 A
```

此时响应主要由限幅决定，而不是 PID 本身。

因此将训练目标调整为：

```text
50 rpm
```

以避免一开始就进入饱和区。

得到一个重要原则：

> 先在非饱和区调 PID 本身，再带真实限幅做工程验证。

---

## 3. Speed PI 调参

最终训练过程中得到一组较好的模型参数：

```text
Speed PI
Kp = 0.1
Ki = 1.7
Kd = 0
```

这组只属于当前简化模型，不可直接搬到实机。

### 现象理解

`Kp`：

```text
决定主要响应强度和速度
```

`Ki`：

```text
消除剩余稳态误差
```

当 Ki 较小时：

```text
前面很快
最后几 rpm 慢慢爬到目标
```

增大 Ki 后：

```text
尾巴变短
稳态误差更快消失
```

### 为什么最后没有使用 Kd

加入 D 后出现明显高频抖振。

原因包括：

```text
Ts = 0.002 s
↓
每个采样点的变化率会被 1/Ts 放大
↓
D 对快速变化非常敏感
```

目标阶跃还会产生 derivative kick。

最终结论：

> Speed PI 已经满足要求时，没有必要强行加入 D。


---

## 1. Position Kp 从小到大

### `Kp = 0.1`

特点：

```text
速度目标小
内环非常容易跟随
位置响应很慢
```

位置逐渐逼近目标，没有明显超调。

### `Kp = 0.3`

特点：

```text
位置响应明显变快
速度目标和实际速度仍然跟得很好
```

属于偏保守但已经实用的范围。

### `Kp = 0.5`

特点：

```text
位置更快
仍然稳定
内环跟踪较好
```

成为较合理的候选区域。

### `Kp = 1.0`

特点：

```text
位置刚性更强
响应更快
速度内环压力进一步增大
```

### `Kp = 1.5`

位置曲线仍然很好看，但速度 Scope 中：

```text
target_rpm 与 actual_rpm 差距明显增大
```

说明：

> 外环已经开始变得过快，内环不再“从容跟随”。

因此真正的外环调参目标不是：

> “位置越快越好。”

而是：

> “在位置响应满足需求的同时，让速度内环仍保留足够跟踪余量。”

---

# 八、位置与速度之间如何取舍

这是今天最重要的串级 PID 理解之一。

### Position Kp 较小

```text
外环变化慢
↓
内环容易跟
↓
速度 target / actual 很贴近
↓
位置响应偏慢、位置刚性偏软
```

### Position Kp 较大

```text
外环快速产生更大的 target_rpm
↓
位置响应更快、更硬
↓
速度内环跟踪压力增大
↓
电流峰值更大
↓
机械冲击和稳定风险提高
```

因此工程上的取舍是：

```text
位置响应 / 刚性
      ↕
内环跟踪余量 / 电流峰值 / 机械冲击 / 稳定余量
```

不是简单追求单一指标最优。

# 九、限幅为什么不会让 PID “没价值”

位置环设置速度限幅，例如：

```text
±50 rpm
```

当位置误差大、Position P 想给：

```text
90 rpm
```

实际会被裁成：

```text
50 rpm
```

这时候运动分成两个阶段：

```text
远离目标
→ 限幅主导
→ 以最大允许速度赶路

靠近目标
→ PID 主导
→ 根据位置误差逐渐减速
```

因此限幅不是让 PID 失效，而是实现：

> “远处限速赶路，近处比例减速停车。”

同样，电流限幅也是：

```text
PID 决定想输出多少
硬件 / 安全限幅决定最多允许多少
```

# 十、负载扰动实验

为了验证参数不是只在“无负载阶跃”下好看，在电机机械模型前加入：

```text
T_net = T_motor - T_load
```

负载 Step：

```text
0 → 0.2 N·m
```

并让扰动在系统已经稳定后再加入。

---

## 1. 抗扰过程

观察到：

```text
负载突然加入
↓
actual_rpm 短暂变负
↓
position 被拉离目标
↓
Position P 产生新的 target_rpm
↓
Speed PI 增加电流
↓
actual_rpm 转正
↓
位置重新回到目标
```

这完整验证了双环抗扰链路。

---

## 2. Position Kp = 0.5 与 1.0 对比

### `Kp = 0.5`

特点：

```text
位置被拉偏更多
恢复较慢
外环更柔和
速度和电流压力较小
```

### `Kp = 1.0`

特点：

```text
位置偏差较小
恢复更快
外环更“硬”
要求更激进的速度和电流
```

因此所谓位置“刚性”可以理解为：

> 同样受到外力扰动时，系统允许位置被拉偏多少，以及多快把它纠正回来。

# 十一、电流 Scope 带来的最终理解

又增加了电流输出 Scope。

### 启动阶段

30°位置阶跃时：

Position `Kp=1`：

```text
target_rpm ≈ 30 rpm
Speed Kp = 0.1
↓
初始电流约 3 A
```

Position `Kp=0.5`：

```text
target_rpm ≈ 15 rpm
↓
初始电流约 1.5 A
```

与 Scope 基本吻合。

由此明确：

```text
Position Kp ↑
→ target_rpm ↑
→ speed error ↑
→ current ↑
→ torque ↑
→ acceleration ↑
→ position 更快
```

所以位置性能变好并不是“免费”的。

### 恒定负载阶段

负载为：

```text
0.2 N·m
```

使用：

```text
Kt = 0.18 N·m/A
```

理论保持电流约：

```text
0.2 / 0.18 ≈ 1.11 A
```

无论 Position Kp 是 0.5 还是 1.0，最后稳定电流都约为 1.1 A。

说明：

> Position Kp 主要改变瞬态恢复有多积极；同样恒定负载最终需要多少维持电流，主要由负载本身决定。


# 十三、最终形成的串级 PID 调参方法

以后上实机时，建议按以下顺序：

```text
1. 固定控制周期、方向、限幅

2. 关闭位置环
   只调速度内环

3. Speed：
   Ki = 0
   Kd = 0
   从小到大调 Kp

4. Kp 合理后逐渐加 Ki
   直到稳态误差满足要求

5. PI 已够用就不加 D

6. 锁死速度环

7. 打开位置外环
   先只用 Position P

8. 从小到大增加 Position Kp
   同时观察：
   - position target / feedback
   - speed target / feedback
   - current output

9. 不要只追求位置最快
   要保证速度内环仍有跟踪余量

10. 先在非饱和工况调参数
    再恢复真实速度/电流限幅

11. 最后加入负载扰动
    检查抗扰能力、恢复速度、电流峰值
```

核心口诀：

> **先内后外；先 P 后 I；D 有明确需要再用；一次只改一层；先非饱和调参数，再带限幅和负载验证；双环必须同时看目标、反馈和控制输出。**

# 十四、今天最重要的错误与纠正

## 错误 1：反馈线没有真正接上

### 表现

```text
Kp=0.05 却几乎到 100 rpm
```

### 原因

实际为开环。

### 纠正

重新连接 actual_rpm 到 Sum(-)。

### 记住

> PID 曲线不符合基本物理判断时，先检查闭环结构，不要先乱改参数。

---

## 错误 2：目标和限幅设置导致一开始就饱和

### 表现

```text
100 rpm + Kp=0.1
→ 直接要求 10 A
```

### 纠正

先用 50 rpm 小阶跃练 PID，再带真实限幅验证。

### 记住

> 调参数和测极限不是同一个实验。

---

## 错误 3：为了“完整 PID”加入 D

### 表现

```text
速度出现高频抖振
```

### 纠正

恢复 PI。

### 记住

> PID 不代表 P、I、D 三项必须全部使用。

---

## 错误 4：只看位置曲线判断 Position Kp

### 表现

Position Kp 越大，位置看起来越漂亮。

### 进一步观察

速度 target / actual 差距变大，电流峰值上升。

### 纠正后的理解

> 外环参数必须同时根据位置、速度跟踪和输出负担判断。
