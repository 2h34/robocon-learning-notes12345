### 3.1 开环与闭环控制

开环控制只发送指令，不检查执行结果：

```text
控制指令
→ 驱动器
→ 电机运动
```

闭环控制会利用编码器等传感器读取实际状态，并根据误差不断修正：

```text
目标值
→ 控制器
→ 驱动器
→ 电机
→ 传感器反馈
→ 再次修正
```

误差为：

$$e = \text{目标值} - \text{实际值}$$

闭环控制具有更好的精度和抗干扰能力。

### 3.2 Linux、MCU 与驱动器分工

| 部分 | 主要任务 |
|---|---|
| Linux 上位机 | 视觉识别、路径规划、任务决策 |
| MCU 下位机 | 读取传感器、实时控制、通信与安全保护 |
| 电机驱动器 | 输出三相电流、控制电机、进行故障保护 |
| 执行机构 | 电机、底盘、机械臂和夹爪等 |

机器人控制链可以概括为：

```text
Linux 上位机
→ MCU 下位机
→ 电机驱动器
→ 电机与机械结构
```

### 3.3 电机基本参数

#### 扭矩

扭矩表示电机产生旋转作用的能力：

$$T = F r$$

单位为：$\mathrm{N\cdot m}$。

扭矩越大，电机带动负载的能力通常越强。

#### 转速

常见单位：

- rpm：每分钟转数；
- rps：每秒转数。

换算关系：$1\ \text{rps} = 60\ \text{rpm}$。

例如：$8\ \text{rps} = 480\ \text{rpm}$。

#### 减速器

减速器的作用是：

```text
降低转速
提高扭矩
```

忽略损耗时：

$$n_{out} = \frac{n_m}{i}$$

$$T_{out} = i\,T_m$$

例如电机转速为 $2400\ \text{rpm}$，减速比为 $8:1$：

$$n_{out} = \frac{2400}{8} = 300\ \text{rpm}$$

### 3.4 电机参数查询

今日查询了 GO-M8010-6、GA2000.4、AK80-9 和 AK80-8 等电机的参数。

重点参数包括：

- KV 值；
- 额定扭矩；
- 峰值电流；
- 额定电流；
- 极对数。

对于数据手册没有明确给出的参数，应标注“官方未给出”，不能根据外观、定子槽数或模糊图片随意推测。

极对数满足：

$$\text{极对数} = \frac{\text{磁极总数}}{2}$$

定子槽数不等于转子磁极数。

### 3.5 电机驱动器作用

MCU 只能输出小功率控制信号，不能直接驱动大功率电机。

三相无刷电机需要 U、V、W 三相变化的电压和电流，因此需要驱动器：

```text
直流电池
→ 电机驱动器
→ 三相电流
→ 无刷电机
```

驱动器还负责：

- 电流、速度和位置控制；
- 编码器反馈处理；
- FOC 控制；
- 过流、欠压和过热保护。

### 3.6 ZDrive 参数整定流程

基本流程为：

```text
连接设备
→ 查看电流、速度和位置波形
→ 设置零位
→ 填写电机和编码器参数
→ 一键写入
→ 打开主电源
→ 参数校准
→ 低速测试
→ 位置模式测试
→ 保存参数
```

连接成功只表示电脑与 ZDrive 通信正常，不代表电机参数已经正确。

### 3.7 主要参数填写原则

| 参数 | 基本原则 |
|---|---|
| 观测方式 | 0 为有感，1 为无感 |
| 编码补偿 | 有感观测时填写 0 |
| 极对数 | 填写电机真实极对数 |
| 电流限制 | 一般不超过峰值电流的 80% |
| 整定电流 | 一般取电流限制的一半左右 |
| 未讲解参数 | 保持默认值 |

例如电机峰值电流为 $40\ \text{A}$：

$$I_{\mathrm{limit}} = 40 \times 80\% = 32\ \text{A}$$

整定电流可初步取：

$$I_{\mathrm{cal}} \approx \frac{32}{2} = 16\ \text{A}$$

### 3.8 编码器与观测方式

编码器可以测量电机的位置和速度，为闭环控制提供反馈。

- 有感观测：使用编码器；
- 无感观测：根据电机电气信号估计转子状态。

机器人低速和位置控制通常更适合使用有感观测。

### 3.9 PID 基础

PID 控制器为：

$$u = K_p e + K_i \int e\,dt + K_d \frac{de}{dt}$$

| 控制项 | 主要作用 |
|---|---|
| P | 根据当前误差进行纠正 |
| I | 累计误差，减小稳态偏差 |
| D | 根据误差变化趋势提前减速 |

直观理解：

```text
P：现在还差多少
I：过去累计差了多少
D：误差变化得有多快
```

PID 会不断读取实际状态、计算误差并重新输出控制量，而不是只计算一次。

### 3.10 故障处理与安全

出现红灯、剧烈抖动、电流异常或电机失控时：

$$\boxed{\text{立即断电}}$$

基本排查顺序：

```text
安全
→ 电源
→ 接线
→ 编码器反馈
→ 参数配置
→ 重新校准
→ 低速测试
```

常见问题：

| 现象 | 优先检查 |
|---|---|
| 低电压报错 | 电源、电池和电源线 |
| 位置波形跳动 | 编码器及其连接 |
| 一使能就抖动 | 极对数、编码器参数和校准结果 |
| 上位机指令无法接收 | 通信链路 |
| 重启后参数恢复旧值 | 是否保存参数 |
| 三相线重新插拔 | 重新进行参数整定 |

## 4. 核心概念

- 机器人运动控制通常需要闭环反馈；
- Linux 负责感知和规划，MCU 负责实时控制；
- 电机选型要同时考虑扭矩和转速；
- 减速器能够降低转速、提高输出扭矩；
- 无刷电机不能直接连接电池，需要电机驱动器；
- 编码器用于测量位置和速度；
- ZDrive 参数应先写入、再校准、测试后保存；
- PID 中 P、I、D 分别处理当前误差、累计误差和误差变化；
- 电机失控时第一步必须断电。
