# 3. 学习过程记录

## 3.1 从气源、压力和流量开始

首先建立最基本的气动系统链路：

```text
气源
↓
气路
↓
电磁阀
↓
气缸
↓
机械机构
```

这里重点区分了两个容易混淆的物理量。

### 压力

压力主要决定气缸能够产生多大的力。

基本关系：

\[
F \approx PA
\]

其中：

- \(P\)：气体压力；
- \(A\)：活塞有效面积；
- \(F\)：理论推力。

气缸缸径越大，活塞面积越大，因此理论输出力越大。

对于普通单杆双作用气缸：

\[
F_{\text{伸出}} \approx P A_{\text{活塞}}
\]

\[
F_{\text{缩回}} \approx P(A_{\text{活塞}}-A_{\text{活塞杆}})
\]

因此一般伸出力会大于缩回力。

### 流量

流量主要影响气缸运动速度。

今天通过“如果气缸动作太快、冲击过大，应该调压力还是流量”的问题确认了这一点：

```text
压力 → 更主要影响力
流量 → 更主要影响速度
```

后续实际 BallGripper 如果夹爪冲击过大，优先考虑调整流量，而不是直接大幅降低整个系统压力。

---

## 3.2 单作用与双作用气缸

### 单作用气缸

一个方向由压缩空气驱动，另一个方向通常由弹簧等方式复位。

例如：

```text
进气
→ 气缸伸出

失气
→ 弹簧复位
```

但实际是“伸出复位”还是“缩回复位”，仍然需要看具体结构。

### 双作用气缸

活塞两侧都可以通气：

```text
A 腔进气 + B 腔排气
→ 一个方向运动

B 腔进气 + A 腔排气
→ 反方向运动
```

今天一开始说到“改变电磁阀朝向，让 B 腔进气”，后面进行了精确修正：

不是物理上去“转动电磁阀”，而是：

```text
控制电磁阀切换工作位置
↓
阀芯改变内部气路连接
↓
B 腔进气、A 腔排气
```

这是一个很重要的机制边界。

---

## 3.3 电磁阀：真正控制的是气路连接关系

今天建立的核心因果链：

```text
线圈状态
↓
阀芯位置
↓
P / A / B / R / S 等接口连接关系
↓
气缸运动方向
```

理解了：

```text
“几位” → 有几个工作位置
“几通” → 有几个气路接口
```

重点学习了常见的 3/2、5/2 换向阀。

例如典型 5/2 阀的两个状态可以抽象为：

```text
状态 1：
P → A
B → R

状态 2：
P → B
A → S
```

因此对双作用气缸来说，电磁阀不仅要给某一腔进气，还要让另一腔能够排气。

---

## 3.4 单电控与双电控

这里专门区分了两个概念：

```text
单作用 / 双作用
→ 描述气缸

单电控 / 双电控
→ 描述电磁阀阀芯如何被驱动
```

### 单电控

典型结构：

```text
一个电磁线圈
+
一个复位弹簧
```

因此通常：

```text
线圈通电
→ 阀芯到一个位置

线圈失电
→ 弹簧使阀芯回到默认位置
```

所以单电控阀通常有明确的失电默认状态。

### 双电控

典型结构：

```text
线圈 A → 状态 A
线圈 B → 状态 B
```

部分双电控阀具有记忆/保持最后阀位的特性，即线圈脉冲结束以后阀芯仍可能保持在当前位置，直到另一线圈动作。

但这一点不能脱离具体型号直接假设，真实工程必须查型号、气动符号或手册。

---

## 3.5 断电、失气和机械状态不是一回事

今天特别纠正了一个非常重要的工程认知：

```text
断电状态
≠
失气状态
≠
气缸机械状态
```

例如：

```text
断电
↓
电磁阀线圈失电
↓
阀芯可能复位
↓
气路改变
↓
气缸才可能运动
```

而失气表示气源压力不足，即使电磁阀仍然正常通电，也可能无法驱动气缸。

对于双作用气缸，失气以后通常也不存在“必然自动缩回”这一结论，最终位置还会受到摩擦、重力、机构载荷和残余气压等影响。

这直接关系到以后 BallGripper 的掉电安全状态设计。

---

## 3.6 限流阀与气缸调速

学习了两种主要节流方式。

### 进气节流（Meter-in）

限制进入驱动腔的气流：

```text
气源
↓
节流
↓
气缸
```

空气进入得越慢，气缸运动通常越慢。

### 排气节流（Meter-out）

允许驱动腔正常进气，但限制另一腔排气：

```text
A 腔进气
B 腔受控排气
```

受控排气会形成一定背压，从而使气缸运动更稳定。

因此在很多普通双作用气缸应用中，经常使用排气节流。

一个容易反直觉但值得记住的关系：

```text
控制气缸伸出速度
→ 常调另一侧腔体的排气

控制气缸缩回速度
→ 常调另一侧腔体的排气
```

以后 BallGripper 实物调试时，应先从较小流量开始，手动测试方向，再逐步加快，不要一开始就全开高速撞击机械限位。

同时机械资料明确提醒：气缸杆不应该长期承担侧向导向力，气缸负责“出力”，机构导向和刚度应该由机械结构承担。

# 4. 队内电磁阀板学习

## 4.1 为什么需要电磁阀板

STM32 GPIO 不应该被简单理解成可以直接驱动电磁阀线圈。

当前队内方案为：

```text
STM32
↓
电磁阀板
（移位寄存器 + 输出）
↓
多个电磁阀
```

一组电磁阀板控制 4 路输出。

---

## 4.2 两根信号线控制 4 路

当前电磁阀板使用两根逻辑信号：

```text
SDA：Serial Data
→ 当前发送的数据位

SCL / CLK：Serial Clock
→ 告诉板子什么时候读取这一位
```

因此本质是：

```text
一根数据线
+
一根时钟线
↓
按时钟逐位串行发送 4 bit
```

---

## 4.3 一个重要纠正：不是 UART

虽然代码参数叫：

```c
usart_channel
```

而且使用 PA9/PA10、PA2/PA3、PC10/PC11 等原串口接口对应的引脚，但是源码实际上配置的是：

```c
GPIO_MODE_OUTPUT_PP
```

并通过：

```c
HAL_GPIO_WritePin(...)
```

手动翻转 GPIO。

因此当前机制是：

```text
借用了 UART 接口位置/引脚
≠
使用 USART 外设
```

不需要 UART 波特率，也没有调用 `HAL_UART_Transmit()`。

---

## 4.4 也不能直接称为标准 I²C

培训 PPT 表述为“类似 IIC 通讯”。

实际代码表现为：

```text
SDA + CLK
+
GPIO bit-banging
```

所以今天形成的准确说法是：

> 当前实现是一种 GPIO 软件模拟的两线同步串行控制方式，时序思想类似 I²C，但根据现有资料不能直接认定为标准 I²C。

# 5. `Solenoid.c/.h` 代码阅读

## 5.1 `Solenoid_t`

结构体：

```c
typedef struct Solenoid_t
{
    GPIO_TypeDef *gpio_port;
    uint16_t gpio_pin_sda;
    uint16_t gpio_pin_clk;
    uint8_t data_prve;
} Solenoid_t;
```

今天明确：

```text
Solenoid_t
≠ 一个电磁阀对象
```

它更接近：

> 一组电磁阀板控制接口的软件上下文。

其中：

```text
gpio_port / gpio_pin_sda / gpio_pin_clk
→ 从哪里发送

data_prve
→ 上一次已经发送的 4 路状态
```

---

## 5.2 `data_prve = 0xF0`

初始化时：

```c
solenoid->data_prve = 0xF0;
```

随后：

```c
solenoid_on(usart_channel, 0);
```

由于：

```text
0xF0 ≠ 0x00
```

第一次 `0x00` 一定会真正发送，而不会被“与上次相同”逻辑提前 `return`。

因此 `0xF0` 在这里可以理解为一个用于保证首次发送成功的哨兵初值。

---

## 5.3 `cmd & 0x0F`

```c
uint8_t data = cmd & 0x0f;
```

只保留低四位：

```text
bit3 bit2 bit1 bit0
```

当前源码注释的软件约定：

```text
bit0 → 通道1
bit1 → 通道2
bit2 → 通道3
bit3 → 通道4
```

例如：

```text
0x05 = 0000 0101
```

表示软件逻辑上：

```text
通道1 = ON
通道2 = OFF
通道3 = ON
通道4 = OFF
```

---

## 5.4 `register_updata()` 的实际发送顺序

关键代码：

```c
if ((*data & 0x08) == 0x08)
{
    SDA = 1;
}
else
{
    SDA = 0;
}

*data <<= 1;
```

`0x08`：

```text
0000 1000
```

因此每次都检查当前 `bit3`。

然后左移：

```text
原 bit2 → 新 bit3
原 bit1 → 下一轮 bit3
原 bit0 → 再下一轮 bit3
```

所以真实代码的发送顺序是：

```text
bit3 → bit2 → bit1 → bit0
```

今天用：

```text
cmd = 0x05
= 0101
```

进行了完整手算：

```text
第1次：bit3 = 0
第2次：bit2 = 1
第3次：bit1 = 0
第4次：bit0 = 1
```

最终发送：

```text
0 → 1 → 0 → 1
```

这里还解决了一个容易混淆的问题：

```text
bit0 对应通道1
```

和：

```text
bit3 最先发送
```

并不冲突。

前者表示**数据的含义**，后者表示**串行传输顺序**。

---

## 5.5 PPT 与真实代码存在的差异

培训 PPT 的伪代码更像：

```text
检查最低位
↓
右移
```

但真实 `Solenoid.c` 是：

```text
检查 bit3
↓
左移
```

因此以后必须以实际运行源码为准。

另外，四个数据位发送完成后源码还有一个额外 CLK 脉冲。

目前没有电磁阀板原理图或具体芯片型号，因此没有擅自判断这个额外脉冲一定是“锁存”“结束信号”或其他具体作用。

当前只记录：

> 源码明确存在 4 个数据时钟 + 1 个额外 CLK 脉冲，其具体硬件语义待原理图/芯片资料确认。

# 6. 当前 `Solenoid` 接口发现的工程问题

当前：

```c
solenoid_on(channel, cmd);
```

里的 `cmd` 表示的是：

> 整块板 4 路输出的完整状态。

不是：

> 只修改其中某一路。

例如：

```text
当前板状态：
0001
```

如果 BallGripper 想打开 bit2，正确的新状态应为：

```text
0001
OR
0100
----
0101
```

如果直接发送：

```text
0100
```

就会同时把原来的 bit0 关闭。

因此后续如果多个气动机构共用同一块电磁阀板，需要进一步设计：

```text
统一维护整块板的 4 bit shadow state
```

或者增加：

```text
SetChannel()
ClearChannel()
```

这样的单通道封装。

当前只是发现并记录这个问题，没有直接修改老师原来的 `Solenoid.c`。

# 8. BlockVacuum 真空吸附学习

## 8.1 真空吸盘为什么能吸住

今天纠正了“真空把方块往里吸”的直觉描述。

更准确的物理模型：

```text
吸盘内部压力降低
↓
外界压力 > 吸盘内部压力
↓
形成压力差
↓
外界大气压把方块压在吸盘上
```

基本关系：

\[
F \approx \Delta P A
\]

因此：

```text
压差越大
→ 理论吸附力越大

有效吸附面积越大
→ 理论吸附力越大

漏气越严重
→ 真空越难建立
→ 吸附能力下降
```

---

## 8.2 两种可能的真空源

### 电动真空泵

```text
电能
↓
电机驱动泵
↓
抽走吸盘内部空气
↓
建立真空
```

### Venturi / Ejector 真空发生器

```text
压缩空气
↓
高速喷射
↓
形成低压区
↓
带走吸盘内部空气
↓
建立真空
```

这里形成的重要理解：

> 真空发生器是在“用正压空气制造低压”，不是把高压气直接吹进吸盘。

目前没有真实硬件信息，所以未确定校内赛最终采用哪一种。

---

## 8.3 释放不等于“关掉真空源”

例如：

```text
真空泵 OFF
```

只能表示泵停止继续抽气，并不一定意味着吸盘内部压力立刻恢复到大气压。

因此释放可能采用：

```text
自然泄压
主动泄压
短时反吹
```

实际方案等待实物确认。

# 9. 真空压力反馈与 BlockVacuum 状态机

学习了真空反馈的基本逻辑：

```text
BlockVacuum_Grab()
↓
启动真空
↓
GRABBING
↓
持续读取压力
↓
达到阈值
↓
GRABBED
```

如果一直吸不上：

```text
超过 GRAB_TIMEOUT
↓
FAULT
```

---

## 9.1 负表压

今天用负表压模型理解真空：

```text
0 kPa
→ 接近大气压

-20 kPa
→ 有一定真空

-50 kPa
→ 更强真空

-62 kPa
→ 比 -50 kPa 真空更深
```

因此如果：

```text
GRABBED 阈值 = -50 kPa
当前压力 = -62 kPa
```

那么：

```c
pressure <= grab_threshold
```

成立，可以认为已经达到设定的吸附判据。

这一点已经能够正确判断。

---

## 9.2 真空开关与压力传感器

今天区分了：

### 真空开关

内部已经完成阈值判断，STM32 只读：

```text
HIGH / LOW
```

### 连续压力传感器

可能通过 ADC 或数字接口获得连续压力值：

```text
-20
-35
-52
-61 kPa
```

然后由软件完成阈值判断。

实际硬件类型目前未知。

---

## 9.3 迟滞 Hysteresis

如果只有一个阈值，例如：

```text
-50 kPa
```

压力在：

```text
-49
-51
-50
-49
...
```

附近波动时，软件状态可能不断切换。

因此可以采用两个阈值：

```text
达到更深真空
→ 进入 GRABBED

真空明显变差
→ 才退出 GRABBED / 进入异常
```

进入和退出使用不同阈值，就是迟滞。

今天只掌握原理，没有为当前机器人虚构具体压力数值。

# 10. Task、Mechanism、Driver、Hardware 的层级进一步明确

今天通过气动系统再次强化了一个非常重要的工程原则：

```text
Driver 输出完成
≠
执行器动作完成
≠
Mechanism 完成
≠
Task 完成
```

例如：

```text
Solenoid ON
≠ BallGripper GRABBED
```

因为中间还有：

```text
电磁阀换向
↓
气缸运动
↓
机械爪运动
↓
完成条件判断
```

同样：

```text
真空源 ON
≠ BlockVacuum GRABBED
```

因为中间还有：

```text
建立真空
↓
压力变化
↓
达到阈值
```

而：

```text
BlockVacuum GRABBED
≠ PickBlockTask DONE
```

因为 Task 后面可能还要：

```text
BlockArm_MoveToSafe()
↓
等待机械臂到安全位置
↓
DONE
```

# 11. 今日遇到的主要问题与纠正

## 问题 1：把气缸换向描述成“改变电磁阀朝向”

### 原理解

为了让气缸反向运动，“改变电磁阀朝向，让 B 腔进气”。

### 修正

实际不是改变阀的物理安装方向，而是：

```text
改变电磁阀工作状态
↓
阀芯切换
↓
内部气路连接发生改变
```

---

## 问题 2：容易默认“通电 = 伸出”

### 修正

实际：

```text
线圈状态
→ 阀位
→ P/A/B/R/S 连接
→ 气缸运动方向
```

A/B 管路接法不同，通电对应的伸缩方向就可能相反。

---

## 问题 3：容易把断电和失气看成同一种情况

### 修正

```text
断电
→ 影响电磁阀线圈和阀位

失气
→ 影响气源压力和执行能力
```

两者完全不是同一个故障模式。

---

## 问题 4：PPT 伪代码与 `Solenoid.c` 实际移位方向不同

### PPT 思路

```text
最低位
+
右移
```

### 实际源码

```text
bit3
+
左移
```

### 最终原则

> 阅读工程时以真实正在使用的源码为准，同时保留“课件是入门简化模型”的认识。

---

## 问题 5：`usart_channel` 容易让人以为正在使用 UART

### 修正

真实代码配置的是普通 GPIO 推挽输出，没有使用 USART 外设。

因此变量名只是历史/接口命名，不能代替对代码机制的判断。

---

## 问题 6：容易把 `Solenoid ON` 直接等同于机构完成

### 修正

底层输出只是动作发起条件。

真正的机构完成应该由：

```text
到位反馈
压力反馈
传感器反馈
或暂时性的时间判据
```

来决定。
