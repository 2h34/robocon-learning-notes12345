```c
typedef enum
```


```c
Ts = 0.002;
```

# 三、关于 `DJI_motor_SetMode()` 的理解过程

这是今天最早澄清的一个问题。

## 1. 最开始的问题

我问：

> 初始化的时候还要调用这个函数吗？  
> 还是把这个函数放在循环里面？

这里的函数是：

```c
DJI_motor_SetMode()
```

一开始容易把它理解成：

```text
初始化函数
或者
需要周期调用的控制函数
```

但后来明确了：

> `DJI_motor_SetMode()` 的职责是“切换控制模式”。

它既不是持续运行的控制函数，也不是必须在初始化阶段调用的函数。

## 2. 正确的职责划分

### `DJI_motor_init()`

负责：

```text
创建初始状态
初始化参数
初始化PID
默认进入 DJ_Disable
```

例如：

```c
motor->mode = DJ_Disable;
```

### `DJI_motor_SetMode()`

负责：

```text
模式真正发生变化时调用一次
```

例如：

```text
Disable → RPM
RPM → Position
Position → Current
Current → Disable
```

模式切换时顺便：

```c
motor->current_cmd = 0;
PID_Reset(&motor->speed_pid);
PID_Reset(&motor->position_pid);
```

因此后来还加了判断：

```c
if (motor->mode != mode)
{
    ...
}
```

防止每次重复设置同一种模式时都不断 Reset PID。

### `DJI_motor_Func()`

这个才是周期运行函数。

```text
每 2 ms
↓
DJI_motor_Func()
↓
检查当前 mode
↓
执行对应控制算法
↓
计算 current_cmd
↓
CAN发送
```

最终形成了清晰区分：

```text
SetMode()
= 告诉电机“以后用什么控制方式”

Func()
= 按照当前控制方式持续执行
```

# 五、位置式 PID 与增量式 PID

今天新的核心知识点是：

```text
增量式 PID
```

此前已经学习和使用的位置式 PID 为：

\[
u[k]
=
K_p e[k]
+
K_i\sum e[k]T_s
+
K_d\frac{e[k]-e[k-1]}{T_s}
\]

它回答的问题是：

> 当前时刻最终应该输出多少？

例如速度环：

```text
target_rpm
↓
error
↓
PID
↓
current_cmd = 500
```

## 1. 增量式 PID 的核心

增量式 PID 不直接先求：

\[
u[k]
\]

而是求：

\[
\Delta u[k]
\]

也就是：

> 相比上一周期，本周期的控制量应该增加或减少多少？

然后：

\[
u[k] = u[k-1] + \Delta u[k]
\]

例如：

```text
上次 current_cmd = 500

本次：
Δu = +30

新的 current_cmd = 530
```

## 2. 增量式 PID 公式

由相邻两个周期的位置式 PID 相减，可以得到：

\[
\Delta u[k]
=
K_p(e[k]-e[k-1])
+
K_i e[k]T_s
+
K_d
\frac{
e[k]-2e[k-1]+e[k-2]
}{T_s}
\]

最终：

\[
u[k] = u[k-1] + \Delta u[k]
\]

---

# 六、增量 PID 对数据结构的新要求

原位置式 PID 主要需要：

```text
last_error
integral
```

而增量式 PID 还需要：

```text
last_last_error
output
```

因此 PID 结构增加了：

```c
double last_last_error;
double output;
```

并加入模式：

```c
typedef enum
{
    PID_MODE_POSITION = 0,
    PID_MODE_DELTA = 1,
} PID_Mode_t;
```

从而一个 PID 模块可以同时支持：

```text
位置式 PID
增量式 PID
```

# 七、自己实现增量式 PID 的过程

我先写出的增量 PID 核心为：

```c
double delta_output =
    pid->Kp * (error - pid->last_error)
    + pid->Ki * error * Ts
    + pid->Kd *
      (error - 2.0 * pid->last_error + pid->last_last_error)
      / Ts;

pid->output += delta_output;
```

这一部分的公式是正确的。

## 1. 第一个问题：Reset 需要清 `output`

一开始 `PID_Reset()` 只清：

```text
last_error
last_last_error
integral
```

后来发现增量 PID 还有一个非常重要的历史状态：

```c
pid->output;
```

因为：

```c
pid->output += delta_output;
```

如果切换模式之后不清 `output`：

```text
上次输出 = 700
↓
Disable
↓
重新进入 RPM
↓
仍然从 700 开始累计
```

显然不合理。

因此最终补上：

```c
pid->output = 0.0;
```

## 2. 第二个问题：第一次计算的 D 冲击

如果第一次直接带入增量公式：

```text
error = 1000
last_error = 0
last_last_error = 0
Ts = 0.002
```

D 项：

\[
K_d
\frac{1000}{0.002}
\]

会非常大。

因此第一次计算不能直接使用完整 D 项。

## 3. 我的最终处理

第一次增量 PID：

```c
if (pid->isfirst_feedback)
{
    pid->last_error = error;
    pid->last_last_error = error;
    pid->isfirst_feedback = 0;

    delta_output =
        pid->Kp * error
        + pid->Ki * error * Ts;
}
```

也就是：

```text
第一次
→ P + I 建立基础输出
→ 不使用 D

第二次开始
→ 正常使用完整增量式 PID
```

这样既防止首次 D 冲击，又避免了：

```text
Ki = 0
并且第一次直接 return 0
```

可能导致电机没有初始驱动力的问题。

# 八、我对位置式和增量式 PID 的疑问

我后来问：

> 我现在采用位置式 PID 或者增量式 PID，有什么区别吗？

这是一个很关键的问题。

最后理解是：

## 位置式 PID

直接回答：

> 现在最终应该输出多少？

```text
error
↓
PID
↓
u[k]
```

## 增量式 PID

先回答：

> 这一次相对于上次应该调整多少？

```text
error变化
↓
PID
↓
Δu
↓
旧输出 + Δu
↓
u[k]
```

## 一个重要结论

不能简单理解为：

```text
增量式 PID 一定比位置式 PID 好
```

实际上在理想条件下，如果离散形式、参数、初始条件一致：

> 两种形式可以得到非常接近甚至数学上等价的控制效果。

真正的区别更多体现在：

```text
输出状态保存
Reset
限幅
模式切换
实现形式
执行器接口
```

所以今天最终没有为了“形式一致”强行把速度环改为增量式。

当前工程中：

```text
增量 PID 代码已经支持
但实际 speed_pid 暂时仍使用位置式
```

这是有意识保留的选择，而不是遗漏。

# 九、如果 PID 算法换了，电机模式代码要不要跟着改

我又问：

> 如果改了 PID 的计算方式，还要改对应模式代码吗？

结论取决于 PID 接口返回什么。

现在的设计是：

```c
PID_Caculate_Delta(...)
{
    ...
    pid->output += delta_output;
    return pid->output;
}
```

也就是说虽然内部算的是：

```text
Δu
```

但函数最终返回的依旧是：

```text
最终完整输出 u
```

因此外部代码仍然可以保持：

```c
double output =
    PID_Caculate(
        &motor->speed_pid,
        motor->target_rpm,
        motor->rpm,
        Ts
    );

motor->current_cmd = (int16_t)output;
```

不能再写：

```c
motor->current_cmd += output;
```

否则就会重复累加。

这让我进一步理解了模块接口设计：

> 外部控制模块只需要知道 PID 最终给出的控制量，不需要知道内部是位置式还是增量式。

# 十三、Current 模式

这是今天最后实际完成的功能。

## 1. 为什么增加 `target_current`

已有：

```c
int16_t current;
int16_t current_cmd;
```

其中：

```text
current
= C610返回的转矩反馈

current_cmd
= 当前周期最终准备发送的控制量
```

如果直接把 `current_cmd` 当作用户目标，会和：

```c
DJI_motor_SetMode()
```

中主动将 `current_cmd = 0` 的安全逻辑发生冲突。

因此新增：

```c
int16_t target_current;
```

明确职责：

```text
target_current
= 用户希望直接施加的控制目标

current_cmd
= 控制模块本周期最终输出
```

## 2. SetCurrent

增加：

```c
void DJI_motor_Set_Current(
    DJI_motor_t *motor,
    int16_t target_current
);
```

并限制：

```text
-10000 ~ 10000
```

逻辑：

```c
if (target_current > 10000)
{
    target_current = 10000;
}
else if (target_current < -10000)
{
    target_current = -10000;
}

motor->target_current = target_current;
```

## 3. CurrentMode

Current 模式本身非常简单：

```c
void DJmotor_CurrentMode(DJI_motor_t *motor)
{
    if (motor == NULL)
    {
        return;
    }

    motor->current_cmd = motor->target_current;
}
```

这并不是“少写了 PID”。

这里的机制层次是：

```text
用户业务逻辑
↓
target_current
↓
STM32 电机模块
↓
current_cmd
↓
C610
↓
C610 内部完成底层 FOC / 电流控制
↓
电机
```

所以：

> `DJ_Current` 是 STM32 直接给 C610 控制量，不需要 STM32 再额外做一个电流 PID。

这是今天一个比较重要的机制边界。

# 十四、无反馈时的安全修正

原来：

```c
if (motor->feedback_valid == 0)
{
    continue;
}
```

后来改成：

```c
if (motor->feedback_valid == 0)
{
    motor->current_cmd = 0;
    continue;
}
```

原因：

> 如果反馈已经无效，不能只是不更新控制量，还应该确保当前发送值回到安全的零输出。

目前 `feedback_valid` 主要还是：

```text
上电首帧保护
```

还没有完成真正的：

```text
CAN 掉线超时检测
```

这属于后续安全功能。

# 十五、今天关于 Current 的最终理解

Current 模式的调用方式：

```c
DJI_motor_Set_Current(&dji_motor[0], 300);
DJI_motor_SetMode(&dji_motor[0], DJ_Current);
```

之后：

```text
每2ms
↓
DJI_motor_Func()
↓
DJ_Current
↓
DJmotor_CurrentMode()
↓
current_cmd = target_current
↓
CAN发送
```

`SetMode()` 即使在模式切换时暂时：

```c
current_cmd = 0;
```

也不会清：

```c
target_current
```

因此下一周期仍能恢复正确目标。

# 十六、今天没有继续做完的 Zero

目前：

```c
case DJ_Zero:
    break;
```

仍然是空的。

在继续写之前，需要先明确：

```text
“Zero”到底表示什么？
```

至少有几个不同概念：

### 1. 软件置零

```text
把当前位置定义成新的 0°
```

不要求电机运动。

### 2. 回到已知零点

```text
已有一个零点
↓
电机主动运动
↓
回到 0°
```

这是一个位置控制过程。

### 3. 机械寻零

例如：

```text
低速移动
↓
触碰限位开关
或
堵转检测
↓
确定机械零点
```

这是更加完整的 Homing 流程。

因此不能简单为了填满：

```c
case DJ_Zero:
```

就随意写代码。

这是下一阶段需要先明确的内容。

```text
SetMode()
≠ 周期控制函数
```

它只在控制模式真正变化时调用。

### 2.

```text
位置式 PID：
算“现在应该输出多少”

增量式 PID：
算“这次应该改变多少”
```

### 3.

增量式 PID 如果函数内部已经：

```c
pid->output += delta_output;
return pid->output;
```

外部就不能再次：

```c
current_cmd += output;
```

否则会重复累加。

### 4.

```text
PID 算法
```

和：

```text
电机模式外层代码
```

可以通过统一接口解耦。

外层只关心最终控制输出。

### 5.

Current 模式：

```text
不是 STM32 做电流 PID
```

而是：

```text
STM32给C610转矩电流控制指令
↓
C610内部完成底层电流/FOC控制
```

### 6.

```text
Zero
```

这个词本身不够明确。

必须先区分：

```text
当前位置置零
回到零点
机械寻零
```

再决定程序怎么写。
