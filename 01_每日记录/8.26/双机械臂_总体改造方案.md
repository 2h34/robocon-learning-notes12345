# 双机械臂总体改造方案

## 1. 改造目标

将当前“单只 BlockArm + 单只 BlockVacuum + 单份取放任务状态”的程序，改造成两只结构相同、非镜像安装的机械臂可独立完成归零、取块、放块、回安全姿态和位置保持。

两只机械臂都具有相同能力；本方案以“左臂”和“右臂”区分它们，而不是把其中一只固定定义为取块臂、另一只固定定义为放块臂。

## 2. 已确认的当前结构与限制

### 2.1 BlockArm 是单实例

`Mechanism/Src/BlockArm.c` 只有：

```c
static BlockArm_t block_arm;
```

其中保存了电机绑定、归零零点、当前位置、目标位置、状态机、微调状态和计数。因此当前只能同时管理一只机械臂。

### 2.2 BlockVacuum 是单实例

`Mechanism/Src/BlockVacuum.c` 只有：

```c
static BlockVacuum_t block_vacuum;
```

它只保存一份吸盘的抓取、释放和故障状态。当前无法表达“左臂吸住、右臂释放”这种独立状态。

### 2.3 PickTask 与 PlaceTask 各自也是单实例

当前存在：

```c
static PickBlockTaskState_t pick_block_task_state;
static PlaceBlockTaskState_t place_block_task_state;
```

它们的接口没有机械臂编号，内部直接调用无参数的 `BlockArm_*()` 与 `BlockVacuum_*()`。因此当前每个任务模块都只能服务于单只臂。

### 2.4 电机层已经是多电机结构

`DJmotor[]` 和 `Zmotor[]` 已经由电机层统一管理；CAN 反馈与定时器控制也统一遍历所有电机。双机械臂不需要复制 `DJmotor.c`、`ZDrive.c`，也不需要增加第二套 CAN 或定时器中断。

## 3. 改造后的职责关系

```text
电机层（保持现状）
DJmotor[] / Zmotor[]
    ├─ 左臂的一台 DJI 与一台 ZDrive
    └─ 右臂的一台 DJI 与一台 ZDrive

机构层（改成双实例）
BlockArm[左] / BlockArm[右]
BlockVacuum[左] / BlockVacuum[右]

任务层（改成按臂编号的双实例）
PickBlockTask[左] / PickBlockTask[右]
PlaceBlockTask[左] / PlaceBlockTask[右]

应用调度层
    ├─ 初始化四台电机对应的两个机构
    ├─ 周期推进左右臂、左右吸盘、左右任务
    └─ 保证同一只臂不会同时运行取块与放块任务
```

原则是：

```text
共享：电机驱动代码、归零算法、BlockArm 状态机代码、固定姿态 switch、任务状态机代码
独立：每只臂的电机指针、零点、目标、当前状态、吸盘状态、任务生命周期
```

## 4. 统一的机械臂编号

在 `Mechanism/Inc/BlockArm.h` 增加固定的机械臂编号：

```c
typedef enum
{
    BLOCK_ARM_LEFT = 0,
    BLOCK_ARM_RIGHT,
    BLOCK_ARM_COUNT
} BlockArmId_t;
```

`BLOCK_ARM_COUNT` 仅用于数组大小和编号范围检查，不代表可对它发动作命令。

所有“这是谁的状态、要控制谁、要读取谁”的接口都应携带 `BlockArmId_t arm_id`。这样上层调用路径中，机械臂身份不会丢失。

## 5. BlockArm 改造

### 5.1 保留私有结构体，改为内部数组

不需要把 `BlockArm_t` 暴露给其他模块，也不需要建立姿态表。

在 `BlockArm.c` 中将：

```c
static BlockArm_t block_arm;
```

改为：

```c
static BlockArm_t block_arm[BLOCK_ARM_COUNT];
```

左右数组元素各自保存：

- 各自的 `DJMotor *`、`Zdrive *`；
- 各自的归零状态和归零计数；
- 各自的 `dji_zero_position`、`zdrive_zero_position`；
- 各自的当前机构坐标和目标机构坐标；
- 各自的到位、微调、停止、复位和故障状态。

### 5.2 增加私有实例获取函数

```c
static BlockArm_t *BlockArm_GetInstance(BlockArmId_t arm_id)
{
    if ((uint32_t)arm_id >= (uint32_t)BLOCK_ARM_COUNT)
    {
        return NULL;
    }

    return &block_arm[arm_id];
}
```

所有公开函数先获得 `BlockArm_t *arm`，然后只操作 `arm->` 字段。非法编号直接返回，避免数组越界和误控制。

### 5.3 修改内部函数参数

将内部辅助函数从隐式访问全局 `block_arm`，改为显式接收当前实例：

```c
static bool BlockArm_DriversBound(const BlockArm_t *arm);
static void BlockArm_UpdateFeedback(BlockArm_t *arm);
static void BlockArm_ApplyPositionTargets(BlockArm_t *arm);
static void BlockArm_SetAutoTarget(BlockArm_t *arm, BlockArmTarget_t target);
static void BlockArm_StartAutoMove(BlockArm_t *arm, BlockArmTarget_t target);
static bool BlockArm_IsReached(BlockArm_t *arm);
static void BlockArm_ApplyFineAdjust(BlockArm_t *arm);
static void BlockArm_StopAndHold(BlockArm_t *arm);
```

函数体内的：

```c
block_arm.dji_target_position
```

统一改为：

```c
arm->dji_target_position
```

状态机顺序、归零判定、参考系公式和现有 TODO 不因双臂改造而改变。

### 5.4 修改 BlockArm 对外接口

在 `BlockArm.h/.c` 中给所有接口增加 `arm_id`：

```c
void BlockArm_Init(BlockArmId_t arm_id,
                   DJMotor *dji_motor,
                   Zdrive *zdrive_motor);
void BlockArm_Home(BlockArmId_t arm_id);
void BlockArm_Stop(BlockArmId_t arm_id);
void BlockArm_Process(BlockArmId_t arm_id);

void BlockArm_MoveToLowPickReady(BlockArmId_t arm_id);
void BlockArm_MoveToHighPickReady(BlockArmId_t arm_id);
void BlockArm_MoveToPlaceBottomReady(BlockArmId_t arm_id);
void BlockArm_MoveToPlaceLevel1Ready(BlockArmId_t arm_id);
void BlockArm_MoveToPlaceLevel2Ready(BlockArmId_t arm_id);
void BlockArm_MoveToSafe(BlockArmId_t arm_id);

void BlockArm_StartFineAdjust(BlockArmId_t arm_id,
                              BlockArmFineAdjustDirection_t direction);
void BlockArm_StopFineAdjust(BlockArmId_t arm_id);
void BlockArm_Reset(BlockArmId_t arm_id);
BlockArmState_t BlockArm_GetState(BlockArmId_t arm_id);
```

### 5.5 固定姿态继续使用现有 switch

不建立姿态表。只把原先的：

```c
static void BlockArm_SetAutoTarget(BlockArmTarget_t target)
```

改为：

```c
static void BlockArm_SetAutoTarget(BlockArm_t *arm,
                                   BlockArmTarget_t target)
```

在现有 `switch` 内继续填写：

```c
arm->dji_target_position = /* 相对本臂零点的 DJI 输出轴角度 */;
arm->zdrive_target_position = /* 相对本臂零点的 ZDrive 输出轴角度 */;
```

由于两臂非镜像、结构相同，两只臂可共用同一套 `switch` 内的姿态角。这里不手动加零点偏移；偏移仍由 `BlockArm_ApplyPositionTargets()` 自动加回。

## 6. BlockVacuum 改造

### 6.1 为什么必须改

若左右臂可以独立抓取和释放，那么必须能同时表示：

```text
左臂：BLOCK_VACUUM_GRABBED
右臂：BLOCK_VACUUM_RELEASED
```

单个 `block_vacuum` 无法表示这种状态。

### 6.2 软件状态改为两份

在 `Mechanism/Src/BlockVacuum.c` 中将：

```c
static BlockVacuum_t block_vacuum;
```

改为：

```c
static BlockVacuum_t block_vacuum[BLOCK_ARM_COUNT];
```

`BlockVacuum` 使用与 `BlockArm` 相同的 `BlockArmId_t arm_id`。这样某臂的姿态控制、吸盘控制和任务控制始终使用同一个编号。

### 6.3 修改吸盘接口

```c
void BlockVacuum_Init(BlockArmId_t arm_id);
void BlockVacuum_Grab(BlockArmId_t arm_id);
void BlockVacuum_Release(BlockArmId_t arm_id);
BlockVacuumState_t BlockVacuum_GetState(BlockArmId_t arm_id);
void BlockVacuum_Process(BlockArmId_t arm_id);
```

### 6.4 真实气路通道是尚未确认的前提

当前 `BlockVacuum.c` 中真实泵阀控制仍是 TODO，`main.c` 只出现 `solenoid_init(3)`。本地源码无法证明左、右吸盘分别对应哪个泵、哪个阀或哪个电磁阀通道。

在写入真实硬件控制前，必须先确定以下实际信息：

- 两臂是否各有独立真空泵；
- 是否共用真空泵但各有独立电磁阀；
- 左右吸盘各自的电磁阀通道；
- 通道的有效电平与“抓取/释放”命令。

若左右臂不能独立控制气路，则无法真正并行执行一只抓取、另一只释放；这是硬件约束，不是软件多实例化可解决的问题。

## 7. PickBlockTask 改造

### 7.1 状态改为按臂保存

在 `Task/Src/PickBlockTask.c` 中将：

```c
static PickBlockTaskState_t pick_block_task_state;
```

改为：

```c
static PickBlockTaskState_t pick_block_task_state[BLOCK_ARM_COUNT];
```

所有私有判断函数也接收 `arm_id`：

```c
static bool PickBlockTask_ArmCanStart(BlockArmId_t arm_id);
static bool PickBlockTask_CanStart(BlockArmId_t arm_id);
```

### 7.2 对外接口改为指定机械臂

```c
void PickBlockTask_Init(BlockArmId_t arm_id);
void PickBlockTask_StartLowPick(BlockArmId_t arm_id);
void PickBlockTask_StartHighPick(BlockArmId_t arm_id);
void PickBlockTask_ConfirmGrab(BlockArmId_t arm_id);
void PickBlockTask_Stop(BlockArmId_t arm_id);
void PickBlockTask_Reset(BlockArmId_t arm_id);
PickBlockTaskState_t PickBlockTask_GetState(BlockArmId_t arm_id);
void PickBlockTask_Process(BlockArmId_t arm_id);
```

内部的全部调用传递相同编号：

```c
BlockArm_MoveToLowPickReady(arm_id);
BlockArm_StopFineAdjust(arm_id);
BlockVacuum_Grab(arm_id);
BlockArm_MoveToSafe(arm_id);
```

这样左臂可以执行取块任务，右臂的取块状态不会被影响。

## 8. PlaceBlockTask 改造

与 PickTask 对称处理：

```c
static PlaceBlockTaskState_t place_block_task_state[BLOCK_ARM_COUNT];
```

对外接口增加 `arm_id`：

```c
void PlaceBlockTask_Init(BlockArmId_t arm_id);
void PlaceBlockTask_StartBottom(BlockArmId_t arm_id);
void PlaceBlockTask_StartLevel1(BlockArmId_t arm_id);
void PlaceBlockTask_StartLevel2(BlockArmId_t arm_id);
void PlaceBlockTask_ConfirmRelease(BlockArmId_t arm_id);
PlaceBlockTaskState_t PlaceBlockTask_GetState(BlockArmId_t arm_id);
void PlaceBlockTask_Process(BlockArmId_t arm_id);
```

内部的 `BlockArm_GetState()`、`BlockVacuum_GetState()`、放块姿态命令、释放命令和回 Safe 命令均使用同一个 `arm_id`。

## 9. 任务冲突规则

即使 PickTask 和 PlaceTask 都改成两份状态，也不能允许同一只臂同时运行两者。

必须由应用调度层保证：

```text
同一 arm_id：PickTask 与 PlaceTask 最多一个处于活动状态
不同 arm_id：允许左臂 PickTask 与右臂 PlaceTask 同时活动
```

这是必要条件。否则两个任务状态机会同时对同一只臂下发不同的 `BlockArm_MoveTo...()` 命令，最终目标以最后一次调用为准，任务状态会彼此失真。

初期可以不新建“总任务管理器”，只在启动任务前检查另一任务是否处于 `IDLE`、`DONE` 或明确的非活动状态。后续动作复杂时，再考虑统一的双臂调度状态机。

## 10. 应用初始化与周期调用

在实际应用的初始化位置绑定不同电机。下标仅为示例，必须替换为实物 ID 对应的数组元素：

```c
BlockArm_Init(BLOCK_ARM_LEFT,
              &DJmotor[LEFT_DJI_INDEX],
              &Zmotor[LEFT_ZDRIVE_INDEX]);
BlockArm_Init(BLOCK_ARM_RIGHT,
              &DJmotor[RIGHT_DJI_INDEX],
              &Zmotor[RIGHT_ZDRIVE_INDEX]);

BlockVacuum_Init(BLOCK_ARM_LEFT);
BlockVacuum_Init(BLOCK_ARM_RIGHT);

PickBlockTask_Init(BLOCK_ARM_LEFT);
PickBlockTask_Init(BLOCK_ARM_RIGHT);
PlaceBlockTask_Init(BLOCK_ARM_LEFT);
PlaceBlockTask_Init(BLOCK_ARM_RIGHT);
```

周期执行也需要分别调用：

```c
BlockArm_Process(BLOCK_ARM_LEFT);
BlockArm_Process(BLOCK_ARM_RIGHT);

BlockVacuum_Process(BLOCK_ARM_LEFT);
BlockVacuum_Process(BLOCK_ARM_RIGHT);

PickBlockTask_Process(BLOCK_ARM_LEFT);
PickBlockTask_Process(BLOCK_ARM_RIGHT);
PlaceBlockTask_Process(BLOCK_ARM_LEFT);
PlaceBlockTask_Process(BLOCK_ARM_RIGHT);
```

当前工作区中未找到这些机构和任务函数的应用调用点，因此需要在实际使用的任务或循环中完成接入；本方案不能从现有源码确定该调用点的具体文件。

## 11. 无需修改的部分

### 11.1 DJI 与 ZDrive 驱动

不复制、不拆分 `DJmotor.c` 和 `ZDrive.c`。它们继续统一控制所有电机。

只需确认：

- 两臂分别绑定不同物理电机；
- CAN ID、总线与数组下标一致；
- 电机数量配置足够；
- 每台电机归零方向正确。

### 11.2 CAN 接收与定时器中断

不增加第二套中断。现有电机层已经在定时器中统一运行控制函数、在 CAN 回调中更新对应电机反馈。

## 12. 实施顺序

1. 增加 `BlockArmId_t`，完成 `BlockArm` 双实例化。
2. 修改应用初始化与周期调用，先验证左右臂可以独立归零和保持。
3. 完成 `BlockVacuum` 双实例化；先确认实际泵阀通道，再写真实输出。
4. 将 PickTask、PlaceTask 改为按 `arm_id` 保存状态和调用接口。
5. 在应用层加入“同一臂取放任务互斥”的启动规则。
6. 单臂验证左、右各自取块和放块流程。
7. 最后验证一臂取块、另一臂放块的并行场景，并观察是否存在机械空间干涉。

## 13. 验证清单

### 软件检查

- 所有旧的无参数 `BlockArm_*`、`BlockVacuum_*`、Task 接口调用都已传入 `arm_id`；
- 左、右 `BlockArm_Init()` 绑定四台不同电机；
- 左、右 `Process()` 均被周期执行；
- 所有以 `arm_id` 为数组下标的函数先检查范围；
- 同一臂不能同时启动 PickTask 和 PlaceTask。

### 实机检查

1. 左臂归零时，右臂不动作；右臂归零时，左臂不动作。
2. 两臂同时归零后，各自机构坐标均以自身机械零点为 `0°`。
3. 左臂保持 Safe 时，右臂移动不会覆盖左臂目标。
4. 左、右吸盘能够独立抓取和释放。
5. 左臂取块与右臂放块同时运行时，两个任务状态、两臂位置目标、两吸盘状态互不串扰。
6. 确认并行动作在实际空间中不会发生碰撞。

## 14. 不应与本次改造混在一起的待办

以下仍然是原项目后续工作，但不属于“单臂改双臂”的结构改动：

- Safe、取块、放块姿态的实测角度；
- `BlockArm_IsReached()` 的到位判断；
- 归零中止、超时、掉线和故障安全处理；
- 微调各方向的双电机组合；
- 真空压力反馈、抓取确认、释放确认；
- 两臂防碰撞与共享空间调度策略。
