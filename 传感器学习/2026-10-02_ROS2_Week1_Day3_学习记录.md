# 2. Day 2 快速检查

## 2.1 Executable 和 Node 不是同一个概念

例如：

```bash
ros2 run hello_ros2 hello_node
```

这里最后的：

```text
hello_node
```

是 **executable 名称**。

而代码中：

```cpp
Node("hello_node")
```

决定的是运行时 ROS2 Node 名称：

```text
/hello_node
```

两者可以同名，也可以不同名。

例如：

```cmake
add_executable(string_publisher src/string_publisher.cpp)
```

而代码中：

```cpp
Node("robot_sender")
```

则：

```bash
ros2 run hello_ros2 string_publisher
```

启动的是 executable：

```text
string_publisher
```

运行时 Node 名则是：

```text
/robot_sender
```

---

## 2.2 `add_executable()` 与 `ros2 run`

```cmake
add_executable(hello_node src/hello_node.cpp)
```

创建的是构建目标，也就是 executable。

安装后：

```bash
ros2 run hello_ros2 hello_node
```

最后的 `hello_node` 对应的就是 executable 名称，而不是 Node 名。

# 3. 一个 ROS2 C++ Node 从 `main()` 到 `spin()` 经历了什么

使用的基础代码：

```cpp
#include "rclcpp/rclcpp.hpp"

class HelloNode : public rclcpp::Node
{
public:
    HelloNode() : Node("hello_node")
    {
        RCLCPP_INFO(this->get_logger(), "Hello ROS2!");
    }
};

int main(int argc, char *argv[])
{
    rclcpp::init(argc, argv);

    auto node = std::make_shared<HelloNode>();

    rclcpp::spin(node);

    rclcpp::shutdown();

    return 0;
}
```

## 3.1 程序生命周期

真正的执行顺序：

```text
程序启动
↓
进入 main()
↓
rclcpp::init()
↓
std::make_shared<HelloNode>()
↓
创建 HelloNode 对象
↓
自动执行 HelloNode 构造函数
↓
Node("hello_node")
↓
建立运行时 ROS2 Node：/hello_node
↓
执行构造函数主体
↓
打印 "Hello ROS2!"
↓
构造函数结束
↓
rclcpp::spin(node)
↓
Executor 持续等待并处理事件
↓
退出 spin
↓
rclcpp::shutdown()
↓
程序结束
```

---

## 3.2 `rclcpp::init()`

```cpp
rclcpp::init(argc, argv);
```

作用：

> 初始化当前程序需要的 ROS2 运行环境。

此时 Node 对象还没有创建。

```cpp

```

表示创建 `HelloNode` 时，先初始化其继承自 `rclcpp::Node` 的部分。

这里：

```cpp

```

## 3.5 `spin()` 的准确理解

```cpp
rclcpp::spin(node);
```

不是：

```text
不断从头运行 Node 代码
```

而是：

> 把 Node 交给 Executor，让 Executor 持续等待并调度这个 Node 的 callback。

核心模型：

```text
事件发生
↓
callback ready
↓
Executor 调度
↓
callback 执行
```

对于最简单的 `HelloNode`，没有 Timer、Subscription 等事件源，因此：

```text
打印一次 Hello ROS2!
↓
进入 spin
↓
持续等待事件
```

程序不会自动退出。

# 4. Publisher Node

## 4.1 使用的核心代码结构

```cpp
class StringPublisher : public rclcpp::Node
{
public:
    StringPublisher()
    : Node("string_publisher")
    {
        publisher_ =
            this->create_publisher<std_msgs::msg::String>(
                "day3_chatter",
                10);

        timer_ =
            this->create_wall_timer(
                1s,
                std::bind(
                    &StringPublisher::timer_callback,
                    this));
    }

private:
    void timer_callback()
    {
        std_msgs::msg::String message;

        message.data = "Hello from C++ publisher";

        RCLCPP_INFO(
            this->get_logger(),
            "Publishing: '%s'",
            message.data.c_str());

        publisher_->publish(message);
    }

    rclcpp::Publisher<std_msgs::msg::String>::SharedPtr publisher_;
    rclcpp::TimerBase::SharedPtr timer_;
};
```

---

## 4.2 从系统结构看 Publisher

先不看细节，结构是：

```text
StringPublisher Node
│
├── Publisher
│      ↓
│   /day3_chatter
│
├── Timer
│   每 1 秒触发一次
│
└── timer_callback()
       ↓
   创建 message
       ↓
   填 message.data
       ↓
   publish(message)
```

---

# 5. 为什么 Publisher 和 Timer 要保存为成员变量

定义：

```cpp
rclcpp::Publisher<std_msgs::msg::String>::SharedPtr publisher_;
rclcpp::TimerBase::SharedPtr timer_;
```

原因：

> 它们不是构造函数中临时使用的对象，而是需要在 Node 整个运行期间持续存在。

例如：

```text
构造函数结束以后
↓
Publisher 还要继续被 callback 使用
↓
Timer 还要继续产生事件
```

因此把它们保存为 Node 的成员变量。

# 10. Subscriber Node

## 10.1 核心结构

```cpp
class StringSubscriber : public rclcpp::Node
{
public:
    StringSubscriber()
    : Node("string_subscriber")
    {
        subscription_ =
            this->create_subscription<std_msgs::msg::String>(
                "day3_chatter",
                10,
                std::bind(
                    &StringSubscriber::topic_callback,
                    this,
                    std::placeholders::_1));
    }

private:
    void topic_callback(
        const std_msgs::msg::String::SharedPtr msg)
    {
        RCLCPP_INFO(
            this->get_logger(),
            "Received: '%s'",
            msg->data.c_str());
    }

    rclcpp::Subscription<std_msgs::msg::String>::SharedPtr
        subscription_;
};
```

---

## 10.2 Subscriber 的结构

```text
StringSubscriber Node
│
└── Subscription
     │
     ├── Topic：/day3_chatter
     ├── Type：std_msgs/msg/String
     └── callback：topic_callback()
```

# 11. Subscriber callback 中的 `msg`

```cpp

    const std_msgs::msg::String::SharedPtr msg)
```

`msg`：

> 当前收到的那条消息。

Publisher 侧：

```cpp
message.data = "Hello from C++ publisher";
```

Subscriber 侧：

```cpp

```

两者对应：

```text
Publisher
message.data
↓
publish()
↓
Topic
↓
Subscriber

```

# 12. Subscriber 中的 `std::bind` 与 `_1`

Timer callback：

```cpp
void timer_callback()
```

没有参数，因此：

```cpp
std::bind(
    &StringPublisher::timer_callback,
    this)
```

即可。

Subscriber callback：

```cpp
void topic_callback(
    const std_msgs::msg::String::SharedPtr msg)
```

需要一个消息参数，因此：

```cpp
std::bind(
    &StringSubscriber::topic_callback,
    this,
    std::placeholders::_1)
```

其中：

```cpp
std::placeholders::_1
```

当前理解为：

> ROS2 调用 callback 时，把它提供的第一个参数，也就是收到的消息，传给 `topic_callback()`。

# 20. 独立修改任务：让 Node 保存状态

目标：

Publisher 连续发布递增计数：

```text
1
2
3
...
```

核心成员变量：

```cpp
int counter_;
```

初始化：

```cpp
counter_ = 0;
```

callback 中：

```cpp
counter_++;
message.data =
    "Hello from C++ publisher: " +
    std::to_string(counter_);
```

---

## 20.1 为什么 `counter_` 要作为成员变量

如果写成局部变量：

```cpp
void timer_callback()
{
    int counter = 0;
}
```

每次进入 callback 都会重新：

```text
counter = 0
```

无法保存上一次的状态。

而成员变量：

```cpp
int counter_;
```

属于整个 `StringPublisher` 对象。

所以：

```text
第一次 callback
counter_ = 1
↓
Node 继续存在
↓
第二次 callback
counter_ = 2
↓
第三次 callback
counter_ = 3
```

状态可以跨 callback 保存。

---

# 21. 一个重要错误：Publisher 和 Subscriber 的成员状态彼此独立

最初在 Subscriber 中也添加了：

```cpp
int counter_;
```

这是没有必要的。

原因：

```text
Publisher 对象中的 counter_
≠
Subscriber 对象中的 counter_
```

它们属于两个不同的 Node 对象，通常还是两个独立进程。

真正跨 Node 传递的是：

```text
Publisher counter_
↓
写入 message.data
↓
publish
↓
Topic
↓
Subscriber 收到 msg
↓
读取 msg->data
```

所以 Subscriber 只需要读取消息，不需要再维护一个同名计数器。

# 22. 今天对 callback 的最终理解

## Timer callback

```text
Timer 到期
↓
callback ready
↓
Executor 调度
↓
timer_callback()
```

## Subscriber callback

```text
消息到达
↓
callback ready
↓
Executor 调度
↓
topic_callback(msg)
```

关键点：

> callback 不是 `main()` 中主动循环调用的。

ROS2 的基础程序结构是典型的事件驱动模式：

```text
先创建通信对象和 callback
↓
spin
↓
事件发生
↓
Executor 调度对应 callback
```

# 26. Day 3 最终能力检查

```cpp
class SensorNode : public rclcpp::Node
{
public:
    SensorNode()
    : Node("sensor_node")
    {
        publisher_ =
            this->create_publisher<std_msgs::msg::String>(
                "sensor_data", 10);

        timer_ =
            this->create_wall_timer(
                500ms,
                std::bind(
                    &SensorNode::timer_callback,
                    this));
    }

private:
    void timer_callback()
    {
        std_msgs::msg::String msg;
        msg.data = "data";
        publisher_->publish(msg);
    }

    rclcpp::Publisher<std_msgs::msg::String>::SharedPtr publisher_;
    rclcpp::TimerBase::SharedPtr timer_;
};
```

已经能够分析：

```text
Node：
/sensor_node

主要 ROS2 组件：
Publisher + Timer

Topic：
/sensor_data

消息类型：
std_msgs/msg/String

Timer 周期：
500 ms

执行链：
spin
↓
Timer 到期
↓
callback ready
↓
Executor 调度
↓
timer_callback()
↓
publish(msg)
↓
/sensor_data
```
