# 三、Topic 发布—订阅模型

## 3.1 基本结构

ROS2 Topic 通信的核心关系：

```text
Publisher
    │
    │ 发布消息
    ▼
  Topic
    │
    │ 订阅消息
    ▼
Subscriber
```

Publisher 与 Subscriber **不直接知道对方是谁**。

Publisher 只需要：

```text
向指定 Topic 发布消息
```

Subscriber 只需要：

```text
订阅指定 Topic
```

因此节点之间具有较好的 **松耦合（Loose Coupling）**。

例如：

```text
/demo_publisher
       │
       ▼
 /lab1/message
       │
       ▼
/demo_subscriber
```

一个 Topic 还可以同时被多个 Subscriber 订阅，例如：

```text
Publisher
    ↓
  Topic
   ├──→ Subscriber A
   └──→ ros2 topic echo
```

频率与周期关系：

\[
f=\frac{1}{T}
\]

例如：

```text
T = 0.5 s
```

则：

```text
f = 2 Hz
```

即每秒发布两条消息。

# 八、QoS 基础理解

QoS：

```text
Quality of Service
服务质量策略
```

用于规定 ROS2 消息如何传输、缓存。

本实验配置：

```python
reliability=ReliabilityPolicy.RELIABLE
```

含义：

```text
采用可靠传输策略
```

```python
history=HistoryPolicy.KEEP_LAST
```

含义：

```text
只保留最近的一部分消息
```

```python
depth=10
```

含义：

```text
保留最近 10 条消息
```

整体可以理解为：

```text
KEEP_LAST
+
depth = 10
↓
最多保留最近 10 条消息
```

当前阶段只需理解基本作用，不需要深入 QoS compatibility。

# 九、ROS2 Timer 与 Executor

## 9.1 创建定时器

代码：

```python
self.timer = self.create_timer(
    0.5,
    self.timer_callback
)
```

含义：

```text
每隔 0.5 s
让 timer_callback 进入可执行状态
```

注意：

```python
self.timer_callback
```

和：

```python
self.timer_callback()
```

不同。

### `self.timer_callback`

表示：

```text
把这个函数本身交给 ROS2
以后由 ROS2 调用
```

### `self.timer_callback()`

表示：

```text
现在立刻执行这个函数
```

因此创建 Timer 时不能加括号。

---

## 9.2 Timer 与 Executor 的关系

更准确的运行机制：

```text
Timer 到期
↓
callback 变为 ready
↓
Executor 发现 ready callback
↓
Executor 调度执行
↓
timer_callback()
```

因此：

```text
Timer
负责“什么时候该运行”

Executor
负责“什么时候真正执行”
```

这与之前学习过的事件触发 + 调度思想比较相似，但 ROS2 callback 本身不能简单等同于 FreeRTOS Task。

# 十一、Publisher 回调函数

Publisher 的定时器回调：

```python
def timer_callback(self):
    msg = String()
    msg.data = f"学号: {self.student_id}, 计数: {self.count}"

    self.publisher.publish(msg)

    self.get_logger().info(f'发布: {msg.data}')

    self.count += 1
```

完整逻辑：

```text
Timer 到期
↓
timer_callback ready
↓
Executor 执行 callback
↓
创建 String 消息
↓
填写 msg.data
↓
publisher.publish(msg)
↓
/lab1/student_msg
↓
count += 1
```

---

# 十二、Publisher 日志与消息发布的区别

真正向 ROS2 Topic 发布消息：

```python
self.publisher.publish(msg)
```

只是打印终端日志：

```python
self.get_logger().info(...)
```

二者作用不同：

```text
publish()
→ ROS2 节点之间通信

logger.info()
→ 给程序员查看运行状态
```

# 十四、Subscriber Callback

Subscriber 与 Timer 使用的是同一套 Executor 思想，只是触发源不同。

Timer：

```text
Timer 到期
↓
timer_callback ready
```

Subscriber：

```text
Topic 收到新消息
↓
message_callback ready
```

然后都由：

```text
Executor
```

负责执行。

---

## 14.1 callback 中的 `msg` 从哪里来

代码：

```python
def message_callback(self, msg):
```

这里的 `msg` 不需要用户自己传入。

流程：

```text
Publisher 构造 msg
↓
publish(msg)
↓
/lab1/student_msg
↓
Subscriber 收到消息
↓
Executor 调用：
message_callback(self, 收到的消息)
↓
收到的消息自动成为 msg
```

因此：

```python
msg.data
```

就是 Publisher 原先填写的消息内容。

# 十五、Subscriber 消息处理

代码：

```python
self.received_count += 1
self.get_logger().info(f'收到: {msg.data}')

if self.received_count % 10 == 0:
    self.get_logger().info(
        f'已累计收到 {self.received_count} 条消息'
    )
```

作用：

```text
每收到一条消息
↓
received_count + 1
↓
打印 msg.data
↓
如果 received_count 是 10 的倍数
↓
额外打印累计消息数
```

例如：

```text
收到 10 条
→ 打印“已累计收到 10 条消息”

收到 20 条
→ 打印“已累计收到 20 条消息”
```

# 十九、为什么 Publisher 计数与 Subscriber 累计数量不相等

实验中观察到：

```text
Publisher 消息计数：116、117、118...
Subscriber 累计数量：90
```

这并不是错误。

原因：

```text
Publisher 先启动
↓
已经发布了一部分消息
↓
Subscriber 后启动
↓
Subscriber 从自己启动后开始统计
```

因此：

```text
Publisher 的 self.count
```

表示：

```text
Publisher 从启动开始累计发布了多少条
```

而：

```text
Subscriber 的 self.received_count
```

表示：

```text
Subscriber 从启动开始累计收到多少条
```

二者没有必须相等的要求。
