# 函数总览：FreeRTOS 主从板 CAN 作业

> 适用工程：STM32F405RG + FreeRTOS + CAN1 + USART1 + TIM3 PWM  
> 本文只整理本作业业务代码实际使用、或与业务代码直接相连的函数、回调和宏。CubeMX/HAL/FreeRTOS 内部的大量底层函数不在本文展开。

## 1. 阅读约定

### 1.1 函数来源

| 标记 | 含义 | 常见例子 |
|---|---|---|
| 项目函数 | 由本项目自己实现 | `Beep()`、`breath_lights()` |
| CMSIS-RTOS2 | 对 FreeRTOS 的统一封装接口 | `osThreadNew()`、`osDelay()` |
| FreeRTOS 原生 | FreeRTOS 自己的宏或 API | `pdMS_TO_TICKS()` |
| STM32 HAL | ST 提供的外设驱动接口 | `HAL_CAN_AddTxMessage()` |
| CubeMX 生成 | 根据 `.ioc` 生成的工程初始化函数 | `MX_CAN1_Init()` |
| C 标准库 | C 语言标准库函数 | `memcpy()`、`snprintf()` |

### 1.2 中断环境

- CAN/UART 回调运行在中断环境，应快速完成并退出。
- 中断中不能调用 `osDelay()`、`osDelayUntil()`、阻塞式 UART 发送或蜂鸣循环。
- 中断中可以调用 `osMessageQueuePut()`，但 `timeout` 必须为 `0`。
- 普通任务中可以使用阻塞等待，让出 CPU 给其他任务。

## 2.1 `running_lights()`

- **位置**：[User/Src/Led_Flow.c:4](User/Src/Led_Flow.c#L4)
- **声明**：[User/Inc/Led_Flow.h:3](User/Inc/Led_Flow.h#L3)
- **原型**：

```c
void running_lights(void);
```

- **功能**：使用静态变量记录当前状态，让 PA4、PA5 两个流水灯交替亮灭。
- **参数**：无。
- **返回值**：无。
- **运行环境**：由 `LED_Task()` 每 100 ms 调用一次。
- **核心知识点**：
  - `static uint8_t run_led` 只初始化一次，函数退出后保留数值。
  - `run_led = !run_led` 在 `0` 和 `1` 之间切换。
  - 内部调用 `HAL_GPIO_WritePin()` 设置高低电平。

```c
running_lights();
```

## 2.2 `Beep()`

- **位置**：[User/Src/Beep.c:4](User/Src/Beep.c#L4)
- **声明**：[User/Inc/Beep.h:4](User/Inc/Beep.h#L4)
- **原型**：

```c
void Beep(uint8_t count);
```

- **功能**：控制 PA8 蜂鸣器响指定次数。
- **参数**：
  - `count`：蜂鸣次数，范围由 `uint8_t` 决定为 `0~255`；当前任务调用前限制到最大 20 次。
- **返回值**：无。
- **运行环境**：只能在普通任务中调用；不能在中断回调中调用。
- **原因**：内部调用 `osDelay(100)`，需要当前任务可以进入阻塞状态。
- **一次蜂鸣时序**：高电平 100 ms + 低电平 100 ms。

```c
Beep(3);  /* 约 600 ms 内完成 3 次蜂鸣 */
```

## 2.4 `Led_Breath_SetCmd()`

- **位置**：[User/Src/Led_Breath.c:7](User/Src/Led_Breath.c#L7)
- **声明**：[User/Inc/Led_Breath.h:5](User/Inc/Led_Breath.h#L5)
- **原型**：

```c
void Led_Breath_SetCmd(uint8_t on_off, uint16_t period_ms);
```

- **功能**：保存呼吸灯开关和周期，计算每一步的更新时间，并重置呼吸相位。
- **参数**：
  - `on_off`：`0` 关闭，非 0 转换为开启。
  - `period_ms`：完整呼吸周期，单位 ms；当前代码限制在 `200~10000 ms`。
- **返回值**：无。
- **计算逻辑**：一个周期分成 100 步，所以 `step_ms = period_ms / 100`。
- **关闭行为**：立即把两路 PWM 比较值清零。

```c
Led_Breath_SetCmd(1, 1000); /* 开启，周期 1000 ms */
Led_Breath_SetCmd(0, 1000); /* 关闭 */
```

## 2.6 `breath_lights()`

- **位置**：[User/Src/Led_Breath.c:52](User/Src/Led_Breath.c#L52)
- **声明**：[User/Inc/Led_Breath.h:7](User/Inc/Led_Breath.h#L7)
- **原型**：

```c
void breath_lights(void);
```

- **功能**：将呼吸相位推进一步，利用余弦曲线计算 PWM 比较值。
- **参数/返回值**：无。
- **相位**：`phase` 在 `0~99` 循环。
- **亮度公式**：

```c
duty = (1.0f - cosf(2.0f * PI * phase / 100.0f))
       * 0.5f * 1999.0f;
```

- **通道关系**：
  - CH1：`duty`
  - CH2：`1999 - duty`，与 CH1 互补呼吸。
- **运行环境**：由 `Breath_Task()` 周期调用，不应放在中断中。

# 3. FreeRTOS 任务入口函数

任务入口统一采用：

```c
void TaskName(void *argument);
```

`argument` 来自 `osThreadNew()` 的第二个参数。当前项目创建任务时传入 `NULL`，所以任务没有使用该参数。

## 3.1 `LED_Task()`

- **位置**：[Core/Src/freertos.c:208](Core/Src/freertos.c#L208)
- **功能**：每 100 ms 调用一次 `running_lights()`。
- **周期方式**：`osKernelGetTickCount()` + `osDelayUntil()`。
- **主从板**：两块板都创建。

## 3.2 `buzzer_Task()`

- **位置**：[Core/Src/freertos.c:229](Core/Src/freertos.c#L229)
- **功能**：阻塞等待 `beep_queue`，取出次数后调用 `Beep()`。
- **队列等待**：`osWaitForever`。
- **业务限制**：`0` 不蜂鸣，大于 20 时限制为 20。
- **主从板**：两块板都创建。

## 3.3 `CAN_Task()`

- **位置**：[Core/Src/freertos.c:253](Core/Src/freertos.c#L253)
- **功能**：阻塞等待 `can_rx_queue`，按照 ID 分发业务消息。
- **共同处理**：`0x123 -> beep_queue`。
- **主板处理**：`0x200 -> float -> vofa_tx_queue`。
- **从板处理**：`0x100 -> BreathCmd_t -> breath_cmd_queue`。
- **说明**：只处理通过硬件过滤、成功进入软件队列的报文，不是总线上的全部报文。

## 3.4 `Noise_Task()`

- **位置**：[Core/Src/freertos.c:298](Core/Src/freertos.c#L298)
- **功能**：每 2 ms 调用一次 `noise_task()`，形成 500 Hz 噪声。
- **主从板**：两块板都创建，但条件编译后发送不同 ID 和帧类型。

## 3.5 `UART_Task()`

- **位置**：[Core/Src/freertos.c:319](Core/Src/freertos.c#L319)
- **功能**：
  1. 启动 UART 中断接收。
  2. 从 `uart_rx_queue` 非阻塞读取 5 字节命令。
  3. 解析开关和周期。
  4. 把命令交给主板 `breath_cmd_queue`。
  5. 组装 CAN `0x100` 发给从板。
  6. 从 `vofa_tx_queue` 读取亮度并按 FireWater 文本发送。
- **主从板**：只在主板创建。
- **循环让出 CPU**：每轮末尾 `osDelay(1)`。

## 3.6 `Breath_Task()`

- **位置**：[Core/Src/freertos.c:440](Core/Src/freertos.c#L440)
- **功能**：启动 PWM、读取呼吸命令，并周期调用 `breath_lights()`。
- **队列读取**：等待时间为 0，避免没有新命令时停止更新亮度。
- **周期**：由 `Led_Breath_GetStepMs()` 决定。
- **主从板**：两块板都创建。

## 3.7 `Float_Task()`

- **位置**：[Core/Src/freertos.c:463](Core/Src/freertos.c#L463)
- **功能**：从板每 10 ms 读取一次亮度，作为 float 通过标准帧 `0x200`、DLC 4 发送。
- **频率**：100 Hz。
- **主从板**：只在从板创建。

# 4. FreeRTOS/CMSIS-RTOS2 核心函数

## 4.1 `osKernelInitialize()`

```c
osStatus_t osKernelInitialize(void);
```

- **来源**：CMSIS-RTOS2。
- **功能**：初始化 RTOS 内核，使系统进入可以创建任务、队列的状态。
- **参数**：无。
- **返回值**：`osOK` 表示成功，其他值表示错误。
- **调用位置**：[Core/Src/main.c:102](Core/Src/main.c#L102)
- **顺序**：必须在 `MX_FREERTOS_Init()` 和 `osKernelStart()` 之前。
- **中断中调用**：不允许。

## 4.2 `osKernelStart()`

```c
osStatus_t osKernelStart(void);
```

- **来源**：CMSIS-RTOS2。
- **功能**：启动任务调度器。
- **参数**：无。
- **返回值**：正常成功后不会回到普通 `main()` 流程；失败时返回错误状态。
- **调用位置**：[Core/Src/main.c:106](Core/Src/main.c#L106)

## 4.3 `osThreadNew()`

```c
osThreadId_t osThreadNew(osThreadFunc_t func,
                         void *argument,
                         const osThreadAttr_t *attr);
```

- **来源**：CMSIS-RTOS2，底层创建 FreeRTOS 任务。
- **功能**：创建一个新任务。
- **参数**：
  - `func`：任务入口函数，例如 `LED_Task`。
  - `argument`：传给任务的参数；当前项目均为 `NULL`。
  - `attr`：任务名称、栈大小、优先级等属性。
- **返回值**：任务句柄；失败时通常为 `NULL`。
- **示例**：

```c
LEDTaskHandle = osThreadNew(LED_Task, NULL, &LEDTask_attributes);
```

- **注意**：创建任务不等于立即直接调用任务函数；调度器启动后才调度它。

## 4.4 `osKernelGetTickCount()`

```c
uint32_t osKernelGetTickCount(void);
```

- **来源**：CMSIS-RTOS2。
- **功能**：返回内核启动以来累计的系统 Tick。
- **返回值**：当前 Tick 数。
- **当前工程**：`configTICK_RATE_HZ = 1000`，所以 1 Tick = 1 ms。
- **用途**：为 `osDelayUntil()` 建立绝对时间基准。

## 4.5 `osDelay()`

```c
osStatus_t osDelay(uint32_t ticks);
```

- **来源**：CMSIS-RTOS2。
- **功能**：让当前任务从现在开始阻塞指定 Tick。
- **参数**：`ticks` 为相对等待时间。
- **返回值**：`osOK` 表示成功；中断中调用会返回错误。
- **示例**：`osDelay(100)` 当前约等于 100 ms。
- **中断中调用**：不允许。

## 4.6 `osDelayUntil()`

```c
osStatus_t osDelayUntil(uint32_t ticks);
```

- **来源**：CMSIS-RTOS2。
- **功能**：让当前任务阻塞到指定的绝对 Tick。
- **参数**：`ticks` 是目标时刻，不是相对延时长度。
- **适用**：100 Hz、500 Hz 等固定周期任务。
- **示例**：

```c
uint32_t last = osKernelGetTickCount();
for (;;) {
    last += 10;
    osDelayUntil(last);
}
```

- **中断中调用**：不允许。

## 4.7 `osMessageQueueNew()`

```c
osMessageQueueId_t osMessageQueueNew(
    uint32_t msg_count,
    uint32_t msg_size,
    const osMessageQueueAttr_t *attr);
```

- **来源**：CMSIS-RTOS2，底层调用 FreeRTOS 队列功能。
- **功能**：创建固定容量、固定单条大小的消息队列。
- **参数**：
  - `msg_count`：最多保存多少条消息。
  - `msg_size`：每条消息占多少字节。
  - `attr`：额外属性；不需要时为 `NULL`。
- **返回值**：队列句柄；失败时为 `NULL`。
- **示例**：

```c
can_rx_queue = osMessageQueueNew(16, sizeof(CanMsg_t), NULL);
```

## 4.8 `osMessageQueuePut()`

```c
osStatus_t osMessageQueuePut(
    osMessageQueueId_t mq_id,
    const void *msg_ptr,
    uint8_t msg_prio,
    uint32_t timeout);
```

- **来源**：CMSIS-RTOS2。
- **功能**：把一条消息的副本放到队尾。
- **参数**：
  - `mq_id`：队列句柄。
  - `msg_ptr`：待复制消息的地址。
  - `msg_prio`：消息优先级；当前 FreeRTOS 适配层忽略它，填 0。
  - `timeout`：队列满时最多等待多少 Tick。
- **返回值**：
  - `osOK`：成功。
  - `osErrorResource`：`timeout=0` 且队列满。
  - `osErrorTimeout`：等待超时。
- **中断使用**：允许，但 `timeout` 必须为 0。
- **注意**：保存的是消息内容副本，不是永久保存原指针。

## 4.9 `osMessageQueueGet()`

```c
osStatus_t osMessageQueueGet(
    osMessageQueueId_t mq_id,
    void *msg_ptr,
    uint8_t *msg_prio,
    uint32_t timeout);
```

- **来源**：CMSIS-RTOS2。
- **功能**：从队首取出一条消息并复制到目标变量，同时从队列删除该消息。
- **参数**：
  - `mq_id`：队列句柄。
  - `msg_ptr`：接收变量地址，例如 `&Msg`。
  - `msg_prio`：不需要消息优先级时填 `NULL` 或 `0`。
  - `timeout`：队列为空时最多等待多少 Tick。
- **每次调用**：只取一条，不会复制整个队列。
- **`timeout=0`**：非阻塞，空队列时立即返回 `osErrorResource`。
- **`timeout=osWaitForever`**：一直阻塞，直到出现消息。

# 5. STM32 HAL：CAN 函数

## 5.1 `HAL_CAN_Init()`

```c
HAL_StatusTypeDef HAL_CAN_Init(CAN_HandleTypeDef *hcan);
```

- **功能**：把 `hcan->Init` 中的波特率、模式、重传等参数写入 CAN 硬件。
- **参数**：CAN 句柄地址，当前为 `&hcan1`。
- **返回值**：`HAL_OK`、`HAL_ERROR` 等。
- **当前配置**：42 MHz / 3 / 14 TQ = 1 Mbps。

## 5.2 `HAL_CAN_ConfigFilter()`

```c
HAL_StatusTypeDef HAL_CAN_ConfigFilter(
    CAN_HandleTypeDef *hcan,
    const CAN_FilterTypeDef *sFilterConfig);
```

- **功能**：把过滤器结构体写入 bxCAN 硬件过滤器。
- **参数**：CAN 句柄、过滤器配置地址。
- **返回值**：`HAL_OK` 表示成功。
- **当前项目**：16 位 ID 列表模式，主板放行 `0x200/0x123`，从板放行 `0x100/0x123`。

## 5.3 `HAL_CAN_Start()`

```c
HAL_StatusTypeDef HAL_CAN_Start(CAN_HandleTypeDef *hcan);
```

- **功能**：启动 CAN 外设，开始正常收发和硬件过滤。
- **参数**：`&hcan1`。
- **返回值**：HAL 状态。

## 5.4 `HAL_CAN_ActivateNotification()`

```c
HAL_StatusTypeDef HAL_CAN_ActivateNotification(
    CAN_HandleTypeDef *hcan,
    uint32_t ActiveITs);
```

- **功能**：开启指定 CAN 事件的中断通知。
- **当前使用**：`CAN_IT_RX_FIFO0_MSG_PENDING`。
- **结果**：FIFO0 有消息时，HAL 最终调用 FIFO0 回调。

## 5.5 `HAL_CAN_GetRxMessage()`

```c
HAL_StatusTypeDef HAL_CAN_GetRxMessage(
    CAN_HandleTypeDef *hcan,
    uint32_t RxFifo,
    CAN_RxHeaderTypeDef *pHeader,
    uint8_t aData[]);
```

- **功能**：从指定硬件 FIFO 取出一条 CAN 报文。
- **参数**：
  - `hcan`：CAN 句柄。
  - `RxFifo`：`CAN_RX_FIFO0` 或 FIFO1。
  - `pHeader`：接收头目标地址。
  - `aData`：接收数据数组。
- **返回值**：`HAL_OK` 表示成功。
- **效果**：成功读取后释放 FIFO 中这一条报文。

## 5.6 `HAL_CAN_AddTxMessage()`

```c
HAL_StatusTypeDef HAL_CAN_AddTxMessage(
    CAN_HandleTypeDef *hcan,
    const CAN_TxHeaderTypeDef *pHeader,
    const uint8_t aData[],
    uint32_t *pTxMailbox);
```

- **功能**：寻找空闲发送邮箱，写入报文并请求 CAN 硬件发送。
- **参数**：CAN 句柄、发送头、数据数组、邮箱结果地址。
- **返回值**：`HAL_OK` 表示已成功提交到邮箱；邮箱满时可能为 `HAL_ERROR`。
- **性质**：非阻塞式提交；真正仲裁和逐位发送由 CAN 硬件完成。
- **注意**：返回 `HAL_OK` 表示进了邮箱，不等于已经被对方业务代码处理。

# 6. STM32 HAL：UART 函数与回调

## 6.1 `HAL_UARTEx_ReceiveToIdle_IT()`

```c
HAL_StatusTypeDef HAL_UARTEx_ReceiveToIdle_IT(
    UART_HandleTypeDef *huart,
    uint8_t *pData,
    uint16_t Size);
```

- **功能**：以中断方式启动一次 UART 接收；达到目标长度或检测到空闲时产生接收事件。
- **参数**：UART 句柄、接收数组地址、最大长度。
- **返回值**：HAL 状态。
- **性质**：非阻塞，启动后立即返回。
- **当前使用**：USART1 接收 5 字节 VOFA 指令。
- **对应回调**：`HAL_UARTEx_RxEventCallback()`。

## 6.2 `HAL_UART_Receive_IT()`（对比参考）

```c
HAL_StatusTypeDef HAL_UART_Receive_IT(
    UART_HandleTypeDef *huart,
    uint8_t *pData,
    uint16_t Size);
```

- **功能**：中断方式接收固定长度数据，通常要收满 `Size` 才完成。
- **对应回调**：`HAL_UART_RxCpltCallback()`。
- **当前项目**：未使用，文档保留用于区分回调。

## 6.3 `HAL_UARTEx_GetRxEventType()`（可选）

```c
HAL_UART_RxEventTypeTypeDef
HAL_UARTEx_GetRxEventType(UART_HandleTypeDef *huart);
```

- **功能**：在 Receive-to-Idle 回调中查询本次属于接收完成、空闲或 DMA 半传输事件。
- **可能结果**：`HAL_UART_RXEVENT_TC`、`IDLE`、`HT`。
- **当前项目**：未调用，只通过 `Size` 判断是否为 5 字节。

## 6.4 `HAL_UART_Transmit()`

```c
HAL_StatusTypeDef HAL_UART_Transmit(
    UART_HandleTypeDef *huart,
    const uint8_t *pData,
    uint16_t Size,
    uint32_t Timeout);
```

- **功能**：阻塞式发送 UART 数据。
- **参数**：UART 句柄、数据地址、字节数、最长等待时间。
- **返回值**：HAL 状态。
- **当前用途**：发送呼吸参数日志和 FireWater 亮度文本。
- **中断中调用**：不建议；当前只在 `UART_Task()` 中使用。

## 6.5 `HAL_UART_IRQHandler()`

```c
void HAL_UART_IRQHandler(UART_HandleTypeDef *huart);
```

- **功能**：HAL 的 UART 中断统一处理函数，分析中断原因并调用对应回调。
- **调用位置**：CubeMX 生成的 `USART1_IRQHandler()`。
- **业务代码**：通常不直接修改该函数。

# 7. STM32 HAL：GPIO 与 PWM

## 7.1 `HAL_GPIO_WritePin()`

```c
void HAL_GPIO_WritePin(GPIO_TypeDef *GPIOx,
                       uint16_t GPIO_Pin,
```

- **功能**：将一个或多个 GPIO 输出为高/低电平。
- **参数**：端口、引脚位掩码、`GPIO_PIN_SET/RESET`。
- **注意**：`RESET` 表示输出低电平，不是恢复引脚默认配置。

## 7.2 `HAL_TIM_PWM_Start()`

```c

```

- **功能**：启动指定定时器通道的 PWM 输出。
- **参数**：定时器句柄、通道。
- **返回值**：HAL 状态。

## 7.3 `__HAL_TIM_SET_COMPARE()`

```c
__HAL_TIM_SET_COMPARE(htim, channel, compare);
```

- **来源**：STM32 HAL 宏，不是普通函数。
- **功能**：修改 PWM 通道比较寄存器值。

- **当前范围**：约 `0~1999`。

# 8. C 标准库和数学库函数

## 8.1 `memcpy()`

```c
void *memcpy(void *dest, const void *src, size_t count);
```

- **头文件**：`<string.h>`。
- **功能**：按字节复制内存。
- **参数**：目标地址、源地址、字节数。
- **返回值**：目标地址 `dest`。
- **当前用途**：
  - CAN 接收数据复制到 `CanMsg_t`。
  - float 与 4 字节 CAN 数据互相复制。
  - 将 6 个噪声字符复制到 CAN 数据区。
- **注意**：不会进行数值格式或字符串格式转换。

## 8.2 `snprintf()`

```c
int snprintf(char *buffer,
             size_t size,
             const char *format,
             ...);
```

- **头文件**：`<stdio.h>`。
- **功能**：按照格式生成字符串，并限制最大缓冲区长度。
- **参数**：输出数组、数组容量、格式字符串、待格式化数据。
- **返回值**：理论上需要写入的字符数，不包括结尾 `\0`；负值表示编码错误。
- **当前用途**：

```c
snprintf(log_buffer, sizeof(log_buffer),
         "Breath %s period=%ums\n", ...);

snprintf(tx_buffer, sizeof(tx_buffer),
         "%.3f\n", brightness);
```

## 8.3 `strlen()`

```c
size_t strlen(const char *str);
```

- **头文件**：`<string.h>`。
- **功能**：计算 C 字符串有效字符数。
- **返回值**：遇到第一个 `\0` 前的字符数量，不包含 `\0`。
- **当前用途**：计算 UART 实际发送长度。
- **要求**：输入必须是正确以 `\0` 结尾的字符串。

## 8.4 `cosf()`

```c
float cosf(float x);
```

- **头文件**：`<math.h>`。
- **功能**：计算单精度浮点余弦。
- **参数**：弧度值，不是角度值。
- **返回值**：`-1.0~1.0`。
- **当前用途**：生成平滑的呼吸亮度曲线。

# 10. 重要宏、运算符和特殊值

## 10.1 `pdMS_TO_TICKS(ms)`

- **来源**：FreeRTOS 原生宏。
- **功能**：把毫秒转换成系统 Tick。
- **示例**：`pdMS_TO_TICKS(10U)` 当前等于 10 Tick。
- **优点**：Tick 频率变化时不必手算。

## 10.2 `sizeof(expression_or_type)`

- **来源**：C 语言运算符，不是函数。
- **功能**：取得类型或对象占用的字节数。
- **当前例子**：
  - `sizeof(float) == 4`
  - `sizeof(CanMsg_t)` 用作 CAN 队列单条大小。
  - `sizeof(tx_buffer)` 用于限制 `snprintf()`。

## 10.3 `osWaitForever`

- **来源**：CMSIS-RTOS2 特殊等待值。
- **功能**：让队列读取等操作一直阻塞，直到条件满足。
- **适用**：CAN 任务、蜂鸣器任务没有其他周期工作时。
- **中断中使用**：不允许。

## 10.4 `(void)函数调用`

- **来源**：C 语言显式类型转换。
- **功能**：表示有意忽略函数返回值。
- **运行效果**：一般与直接不接收返回值相同；可能减少静态检查警告。
- **更可靠做法**：保存并检查返回状态。

## 10.5 `CAN_STD_ID_16BIT(id)`

- **来源**：项目在 `can.c` 中定义的宏。
- **功能**：把 11 位标准 CAN ID 左移 5 位，放入 bxCAN 16 位过滤槽规定的位置。
- **示例**：`0x123 << 5 = 0x2460`。
- **注意**：只改变过滤寄存器编码，总线 ID 仍然是 `0x123`。

## 10.6 `#if defined(IS_MASTER_BOARD)` / `IS_SLAVE_BOARD`

- **来源**：C 预处理条件编译。
- **功能**：同一份源码生成主板和从板两个不同固件。
- **主板保留**：UART 任务、接收 `0x200`、发送标准噪声 `0x012`。
- **从板保留**：Float 任务、接收 `0x100`、发送扩展噪声 `0x02010101`。
- **发生时机**：编译前，不是运行时判断。

# 12. 常见误区

1. `osThreadNew()` 是系统创建任务的函数，`LED_Task()` 才是项目任务内容。
2. `osMessageQueueGet()` 每次只取一条消息，不会复制整个队列。
3. `timeout=0` 是立即返回，`osWaitForever` 是阻塞当前任务，不是卡住整个系统。
4. CAN 硬件 FIFO 与 FreeRTOS 软件队列不是同一个东西。
5. `GPIO_PIN_RESET` 表示低电平，不是恢复引脚默认状态。
6. `HAL_CAN_AddTxMessage()` 成功表示提交到邮箱，不代表业务对端已经处理。
7. `HAL_UARTEx_RxEventCallback()` 不只可能由空闲触发，接收满目标长度也会触发。
8. `HAL_UART_Receive_IT()` 对应 `HAL_UART_RxCpltCallback()`，Receive-to-Idle 对应 RxEvent 回调。
9. `memcpy()` 只复制原始字节，不会把 float 转换成十进制字符串。
10. FireWater 需要文本数字和换行；JustFloat 才直接发送二进制 float。
11. `osDelay()` 只能阻塞普通任务，不能在 CAN/UART 中断回调中使用。
12. CubeMX 重新生成时，`USER CODE` 标记之外的手动修改可能被覆盖。
