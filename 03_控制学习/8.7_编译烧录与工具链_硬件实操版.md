## 四、F7 完成的步骤

按下 `F7` 后，Keil 主要完成以下过程：

1. **预处理**：处理 `#include`、`#define` 和条件编译等内容；
2. **编译**：将 `.c` 文件转换为目标文件 `.o`；
3. **汇编**：将启动文件等汇编代码转换为目标文件；
4. **链接**：将多个 `.o` 文件和库组合为完整程序；
5. **生成固件**：生成 `.axf` 和 `.hex` 文件。

整体流程为：

```text
C 源代码
→ 预处理
→ 编译
→ 汇编
→ 链接
→ .axf / .hex
```

## 五、认识编译产物

在 `MDK-ARM` 的编译输出目录中找到了：

```text
main.o
gpio.o
led.o
startup_stm32h723xx.o
keil_proj_demo.axf
keil_proj_demo.hex
```

各类文件作用如下：

| 文件类型 | 作用 |
| --- | --- |
| `.o` | 单个源文件或汇编文件编译后生成的目标文件 |
| `.axf` | 链接后生成的可执行映像，通常包含符号和调试信息 |
| `.hex` | 用于写入单片机 Flash 的固件文件 |
| `.d` | 记录源文件依赖的头文件 |
| `.map` | 记录程序地址分配和空间占用情况 |

### F8 的作用

按下 `F8` 后，Keil 通过 ST-Link 将编译生成的程序映像写入 STM32 芯片的 Flash。

本次实际下载时，Keil 输出：

```text
Load "keil_proj_demo\keil_proj_demo.axf"
Erase Done.
Programming Done.
Verify OK.
Flash Load finished.
```

说明下载过程完成了：

```text
擦除目标扇区
→ 写入程序
→ 校验程序
```

## 六、为什么修改代码后必须重新编译和下载

STM32 实际运行的是 Flash 中的机器码，而不是电脑上的 `.c` 源文件。

因此修改代码后，必须完成：

```text
修改代码
→ 保存
→ F7 重新编译
→ F8 重新下载
→ 复位运行
```

- 只修改源码而不编译：不会生成新的固件；
- 只编译而不下载：新程序只保存在电脑中；
- 只下载而不重新编译：可能写入的仍然是旧固件；
- 下载后复位：CPU 才会从 Flash 中重新执行新程序。

## 七、添加 `user` 组件

### 1. 新建 Group

在 Keil 工程中创建新 Group：

```text
user
```

Group 是 Keil 工程中的源码分组，不等同于磁盘文件夹。

### 2. 添加源文件

将以下文件加入 `user` Group：

```text
user/src/user_beep.c
```

Keil 不会自动扫描目录中的所有 `.c` 文件，只有加入工程的源文件才会参与编译。

### 3. 添加头文件搜索路径

在：

```text
Options for Target
→ C/C++
→ Include Paths
```

中添加：

```text
..\user\inc
```

该路径用于让编译器找到：

```text
user/inc/user_beep.h
```

### 4. 修改 `main.c`

在 `Core/Src/main.c` 中加入：

```c
#include "user_beep.h"
```

完成后按 `F7` 编译，结果为：

```text
0 Error(s), 0 Warning(s)
```

说明 `user` 组件配置成功。

### 5. VS Code 提示说明

VS Code 曾提示：

```text
无法打开源文件 "user_beep.h"
```

但 Keil 编译正常，因此该提示只是 VS Code IntelliSense 的 `includePath` 未同步，不影响本次 Keil 工程编译和下载。

## 八、移除 Include Paths 后的编译错误

临时移除：

```text
..\hardware\inc
```

再次按 `F7`，出现：

```text
../user/src/user_beep.c(7): error: 'buzzer.h' file not found
```

### 原因分析

`user_beep.c` 中包含：

```c
#include "buzzer.h"
```

而 `buzzer.h` 位于：

```text
hardware/inc
```

移除 `hardware/inc` 后，编译器无法找到该头文件，因此在编译阶段报错。

### 结论

`Include Paths` 的作用是：

> 告诉编译器到哪些目录中查找 `.h` 头文件。

恢复 `..\hardware\inc` 后，工程重新编译成功。

---

## 九、移除 `.c` 文件后的链接错误

将以下文件从 `hardware` Group 中移除：

```text
hardware/src/buzzer.c
hardware/src/led.c
```

再次按 `F7`，出现：

```text
Undefined symbol buzzer_init
Undefined symbol led_on
Undefined symbol led_off
Undefined symbol buzzer_on
Undefined symbol buzzer_off
```

### 原因分析

此时头文件仍能找到，函数声明也存在，但 `buzzer.c` 和 `led.c` 没有参与编译，链接器无法找到函数的具体实现。

### 编译错误与链接错误对比

| 情况 | 阶段 | 典型报错 | 原因 |
| --- | --- | --- | --- |
| 缺少 Include Path | 编译阶段 | `file not found` | 编译器找不到头文件 |
| 缺少 `.c` 文件 | 链接阶段 | `Undefined symbol` | 链接器找不到函数实现 |

重新添加 `buzzer.c` 和 `led.c` 后，编译恢复为：

```text
0 Error(s), 0 Warning(s)
```

## 十、修改程序参数

在 `Core/Src/main.c` 中，将：

```c
#define DELAY_MS 250U
```

修改为：

```c
#define DELAY_MS 500U
```

重新编译成功。

理论上 LED 每次点亮和熄灭的延时时间由 `250 ms` 增加到 `500 ms`，因此闪烁速度会变慢。

## 十二、ST-Link 与下载配置

### 1. 在 Keil 中选择调试器

进入：

```text
Project
→ Options for Target
→ Debug
```

选择：

```text
ST-Link Debugger
```

进入 `Settings` 后，Keil 能识别到：

```text
Unit: ST-LINK/V2
Port: SW
ARM CoreSight SW-DP
```

说明 Keil 已经通过 SWD 与目标芯片建立连接。

### 2. Flash Download 设置

在 `Flash Download` 页面中确认：

- 选择 `Erase Sectors`；
- 勾选 `Program`；
- 勾选 `Verify`；
- 使用适用于 STM32H72x/H73x 的 Flash 编程算法。

本次按作业要求，在下载完成后手动按 `NRST` 复位键，因此不强制勾选 `Reset and Run`。
