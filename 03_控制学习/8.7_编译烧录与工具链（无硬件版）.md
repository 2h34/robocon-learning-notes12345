## 四、F7 编译过程

按下 `F7` 后，Keil 主要完成以下步骤：

1. **预处理**  
   处理 `#include`、`#define` 和条件编译等内容。

2. **编译**  
   将 `.c` 源文件转换为目标文件 `.o`。

3. **汇编**  
   将启动文件等汇编代码转换为目标文件。

4. **链接**  
   将多个 `.o` 文件和库组合为完整的可执行映像。

5. **生成固件**  
   生成 `.axf` 和 `.hex` 等文件。

整体流程可表示为：

```text
C 源代码
→ 预处理
→ 编译
→ 汇编
→ 链接
→ .axf / .hex
```

## 五、认识编译产物

在 `MDK-ARM` 的编译输出目录中找到了以下文件：

```text
main.o
gpio.o
led.o
startup_stm32h723xx.o
keil_proj_demo.axf
keil_proj_demo.hex
```

各类文件的作用如下：

| 文件类型 | 作用 |
| --- | --- |
| `.o` | 单个源文件或汇编文件编译后生成的目标文件 |
| `.axf` | 链接后生成的可执行映像，通常还包含符号和调试信息 |
| `.hex` | 用于写入单片机 Flash 的固件文件 |
| `.d` | 依赖关系文件，记录源文件依赖的头文件 |
| `.map` | 链接映射文件，可查看程序各部分的地址和空间占用 |

### F8 的作用

按下 `F8` 后，Keil 会通过 ST-Link 将编译生成的固件写入 STM32 芯片的 Flash。

本次由于没有 ST-Link 硬件，没有实际执行下载操作。

## 六、为什么修改代码后必须重新编译和下载

STM32 芯片实际运行的是 Flash 中的机器码，而不是电脑上的 `.c` 源文件。

修改代码后，芯片中的旧程序不会自动变化，因此必须完成：

```text
修改代码
→ 保存
→ F7 重新编译
→ F8 重新下载
→ 复位运行
```

- 只修改源码而不编译：不会生成新的固件；
- 只编译而不下载：新固件只保存在电脑中；
- 只下载而不重新编译：可能写入的仍然是旧固件；
- 下载后复位：CPU 才会从 Flash 中重新执行新程序。

## 七、添加 `user` 组件

### 1. 新建 Group

在 Keil 工程中创建新 Group：

```text
user
```

Group 是 Keil 工程中的源码分组，不等同于磁盘文件夹。

### 2. 添加源文件

将以下文件加入 `user` Group：

```text
user/src/user_beep.c
```

Keil 不会自动扫描工程目录中的所有 `.c` 文件，只有加入工程的源文件才会参与编译。

### 3. 添加头文件搜索路径

在：

```text
Options for Target
→ C/C++
→ Include Paths
```

中添加：

```text
..\user\inc
```

该路径用于让编译器找到：

```text
user/inc/user_beep.h
```

### 4. 修改 `main.c`

在 `Core/Src/main.c` 中加入：

```c
#include "user_beep.h"
```

完成后按 `F7` 编译，结果为：

```text
0 Error(s), 0 Warning(s)
```

说明：

- `user_beep.c` 已经参与编译；
- `user_beep.h` 可以被编译器找到；
- `user` 组件配置成功。

### 5. VS Code 提示说明

VS Code 曾提示：

```text
无法打开源文件 "user_beep.h"
```

但 Keil 编译结果正常，因此该提示只是 VS Code IntelliSense 的 `includePath` 尚未同步，不影响本次 Keil 作业。

本次作业判断工程是否正确，主要以 Keil 的编译结果为准。

## 八、移除 Include Paths 后的编译错误

临时移除：

```text
..\hardware\inc
```

再次按 `F7`，出现报错：

```text
../user/src/user_beep.c(7): error: 'buzzer.h' file not found
```

### 原因分析

`user_beep.c` 中包含：

```c
#include "buzzer.h"
```

而 `buzzer.h` 位于：

```text
hardware/inc
```

移除 `hardware/inc` 后，编译器不知道去哪里寻找该头文件，因此在编译阶段报错。

### 结论

`Include Paths` 的作用是：

> 告诉编译器到哪些目录中查找 `.h` 头文件。

恢复 `..\hardware\inc` 后，工程重新编译成功。

---

## 九、移除 `.c` 文件后的链接错误

将以下文件从 `hardware` Group 中移除：

```text
hardware/src/buzzer.c
hardware/src/led.c
```

再次按 `F7`，出现以下错误：

```text
Undefined symbol buzzer_init
Undefined symbol led_on
Undefined symbol led_off
Undefined symbol buzzer_on
Undefined symbol buzzer_off
```

### 原因分析

此时：

- `buzzer.h` 和 `led.h` 仍然可以找到；
- 函数声明仍然存在；
- 但 `buzzer.c` 和 `led.c` 没有参与编译；
- 链接器无法找到函数的具体实现。

因此出现 `Undefined symbol` 链接错误。

### 编译错误和链接错误的区别

| 情况 | 阶段 | 典型报错 | 原因 |
| --- | --- | --- | --- |
| 缺少 Include Path | 编译阶段 | `file not found` | 编译器找不到头文件 |
| 缺少 `.c` 文件 | 链接阶段 | `Undefined symbol` | 链接器找不到函数实现 |

重新将 `buzzer.c` 和 `led.c` 添加回 `hardware` Group 后，编译结果恢复为：

```text
0 Error(s), 0 Warning(s)
```

## 十、修改程序参数

在 `Core/Src/main.c` 中，将：

```c
#define DELAY_MS 250U
```

修改为：

```c
#define DELAY_MS 500U
```

重新按 `F7` 编译，结果正常。

理论上，LED 每次点亮和熄灭的延时时间由 `250 ms` 增加到 `500 ms`，因此闪烁速度会变慢，周期约变为原来的两倍。
