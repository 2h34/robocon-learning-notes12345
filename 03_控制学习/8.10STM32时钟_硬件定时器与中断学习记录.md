## 二、新学习的知识点

### 1. STM32 时钟基本结构

STM32 中并不是所有外设都直接使用 `SYSCLK`。

本工程中的主要时钟关系为：

```text
SYSCLK = 550 MHz
   ↓ AHB /2
HCLK = 275 MHz
   ↓ APB1 /2
PCLK1 = 137.5 MHz
   ↓ 当前 Timer 时钟配置
APB1 Timer Clock = 275 MHz
```

因此，本次 TIM6 计算 PSC、ARR 时使用：

```text
TIM6 Clock = 275 MHz
```

需要记住：**PCLK 和 Timer Clock 不一定相同，实际计算前应在 CubeMX 中确认 Timer Clock。**

### 2. PSC、CNT、ARR

`PSC = Prescaler`，预分频器：

```text
CNT Clock = TIM Clock / (PSC + 1)
```

`CNT = Counter`，计数器：按照 CNT Clock 自动计数。

`ARR = Auto-Reload Register`，自动重装载寄存器：简单向上计数时，CNT 从 `0` 数到 `ARR`，一轮实际计数次数为：

```text
ARR + 1
```

本次最终设置：

```text
TIM6 Clock = 275 MHz
PSC = 27499
CNT Clock = 10 kHz
一个 CNT 节拍 = 0.1 ms
ARR = 4999
Timer 周期 = 500 ms
```

### 3. Update Event

CNT 完成一轮计数后产生 `Update Event`（更新事件）。

它只是 Timer 内部事件，**不等于中断本身**。

### 4. IRQ、NVIC、ISR

- `IRQ = Interrupt Request`：中断请求，外设向 CPU 发出“需要处理”的请求。
- `NVIC = Nested Vectored Interrupt Controller`：嵌套向量中断控制器，负责管理中断请求、使能状态和优先级。
- `ISR = Interrupt Service Routine`：中断服务程序，是 CPU 响应中断后进入的代码入口。

TIM6 的中断入口：

```c
void TIM6_DAC_IRQHandler(void)
{
    HAL_TIM_IRQHandler(&htim6);
}
```

### 5. HAL Handler 与 Callback

`HAL = Hardware Abstraction Layer`，硬件抽象层，是 ST 提供的库。

本次完整调用链：

```text
TIM6 Update Event
    ↓
IRQ
    ↓
NVIC
    ↓
ISR：TIM6_DAC_IRQHandler()
    ↓
HAL_TIM_IRQHandler(&htim6)
    ↓
HAL_TIM_PeriodElapsedCallback()
    ↓
用户自己的 LED 逻辑
```

其中：

- `TIM6_DAC_IRQHandler()`：ISR，中断入口；
- `HAL_TIM_IRQHandler()`：HAL 的 Timer 中断处理函数；
- `HAL_TIM_PeriodElapsedCallback()`：HAL 处理周期到达事件时调用的用户回调接口。

注意：**Callback 执行时仍处于中断上下文中，并不是中断结束后才执行。**

### 6. HAL_GetTick 软件定时与硬件 Timer 的区别

之前的 `HAL_GetTick()` 非阻塞调度，本质是主循环轮询：

```text
while(1)
→ CPU 主动检查当前时间
→ 判断任务是否到期
→ 到期后执行
```

如果 `while(1)` 中某个任务执行时间过长，就可能不能及时检查其他任务。

硬件 Timer 则由外设自己计数，到期后主动向 CPU 发送中断请求，因此更适合需要较稳定周期触发的任务。

### 7. GPIO 翻转函数

本次学习了：

```c
HAL_GPIO_TogglePin(GPIOx, GPIO_Pin);
```

作用：翻转指定 GPIO 当前输出电平。

本工程 LED1 为 PB3，因此可以写：

```c
HAL_GPIO_TogglePin(GPIOB, GPIO_PIN_3);
```

也可以使用工程已有宏：

```c
HAL_GPIO_TogglePin(LED_GPIO_PORT, LED1_PIN);
```

```text
Pinout & Configuration
→ Timers

→ Activated
```

最终配置：

```text

Counter Period = 4999
Counter Mode = Up
```

```c
htim6.Init.Prescaler = 27499;
htim6.Init.CounterMode = TIM_COUNTERMODE_UP;
htim6.Init.Period = 4999;
```

## 四、自己完成的代码

### 1. 启动 TIM6 中断

CubeMX 初始化 Timer 不代表 Timer 已经开始运行，因此在 `MX_TIM6_Init()` 之后、`while(1)` 之前加入：

```c
HAL_TIM_Base_Start_IT(&htim6);
```

作用：启动 TIM6 计数并启用更新中断。

### 2. 周期回调

在 `USER CODE BEGIN 4` 中加入：

```c
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM6)
    {
        HAL_GPIO_TogglePin(GPIOB, GPIO_PIN_3);
    }
}
```

实现效果：TIM6 每 500 ms 到期一次，LED1 翻转一次。

## 五、学习过程中遇到的问题与纠正

### 1. 频率与周期单位混淆

学习过程中曾把 `MHz / kHz` 与 `ms / μs` 混淆。

最终明确：

```text
单个节拍时间 = 1 / 频率
```

例如：

```text
10 kHz → 0.1 ms / 节拍
```

### 2. PSC 初始设置不能满足 500 ms

一开始考虑：

```text
PSC = 274
CNT Clock = 1 MHz
```

如果 Timer 周期设为 500 ms，则需要：

```text
ARR = 499999
```

但 TIM6 的 ARR 为 16 位，无法容纳该值。

因此重新选择：

```text
PSC = 27499
CNT Clock = 10 kHz
ARR = 4999
```

成功满足 500 ms 周期。

### 3. Update Event 与中断混淆

最终明确：

```text
Update Event
→ 中断使能后产生 IRQ
→ NVIC 管理
→ CPU 进入 ISR
```

Update Event 不是中断本身。

### 4. IRQ、ISR、HAL、Callback 概念一度混淆

经过实际代码重新梳理后：

```text
IRQ      = 中断请求
NVIC     = 管理中断请求
ISR      = CPU 响应后的中断入口
HAL      = ST 提供的硬件抽象层库
Callback = HAL 调用的用户逻辑接口
```

Callback 不是第二次中断，而是当前中断处理过程中被 HAL 调用的函数。

### 5. 原有 `flow_led()` 会干扰验证

原工程 `while(1)` 中还在执行：

```c
flow_led();
```

它也会控制 LED，因此验证 TIM6 时暂时将其注释，避免两个逻辑同时修改 LED 状态。

### 6. Flash 下载失败

下载时出现：

```text
Error: Flash Download failed - Target DLL has been cancelled
```

由于此前已经编译通过，因此判断问题不在编译层，而在**下载/调试连接层**。

后续处理连接问题后成功完成下载。

### 7. 找不到复位按键

开发板上能看到 `NRST` 复位电路丝印，但没有明显实体复位按键。

最终通过：

```text
断电 → 重新上电
```

让 MCU 重新启动并完成验证。

## 八、今日最值得记住的一点

> 硬件 Timer 自己按照 Timer Clock 计数，CNT 到达 ARR 后产生 Update Event；中断使能后产生 IRQ，经 NVIC 管理后 CPU 进入 ISR。ISR 调用 HAL 的中断处理函数，HAL 再根据事件调用用户 Callback，最终执行用户自己的控制逻辑。
