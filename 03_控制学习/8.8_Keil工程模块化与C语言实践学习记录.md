## 三、C语言基础知识复习

### 1. 变量与作用域

理解了局部变量只能在其所在函数或代码块中使用。

例如 `main()` 与 `blink_led()` 中即使都存在 `delay_ms`，它们也是两个不同的局部变量。

### 2. 函数声明与函数定义

函数声明：

```c
void beep(uint32_t beep_ms);
```

作用是提前告诉编译器函数名称、参数和返回值类型。

函数定义：

```c
void beep(uint32_t beep_ms)
{
    buzzer_on();
    HAL_Delay(beep_ms);
    buzzer_off();
}
```

包含函数真正执行的代码。

### 3. 形参与实参

例如：

```c
beep(BEEP_MS);
```

其中：

- `beep_ms` 是形参；
- `BEEP_MS` 是调用函数时传入的实参。

### 4. 控制结构

进一步理解了：

- `for`：固定次数循环；
- `while`：条件满足时持续循环；
- `if / else`：进行条件判断；
- `switch / case`：根据变量的不同取值执行不同程序分支。

## 五、模块化编程实践

### 1. 新建报警系统模块

新建：

```text
user/inc/alarm_system.h
user/src/alarm_system.c
```

理解了：

```text
.h 文件
→ 主要负责函数声明和对外接口

.c 文件
→ 主要负责函数具体实现
```

### 2. 头文件保护

使用：

```c
#ifndef ALARM_SYSTEM_H
#define ALARM_SYSTEM_H

...

#endif
```

作用是防止同一个头文件被重复包含。

### 3. 标准整数类型

在头文件中使用：

```c
uint8_t
uint16_t
uint32_t
```

时加入：

```c
#include <stdint.h>
```

理解了头文件应尽量自己包含其所依赖的数据类型定义。

### 4. Keil 工程配置

将 `alarm_system.c` 加入 Keil 的 `user` Group 中。

进一步理解：

```text
Include Paths
→ 让编译器找到 .h 文件

Keil Group 中加入 .c
→ 让源文件真正参与编译
```

## 六、函数搬移与工程分层

将原来位于 `main.c` 中的：

```c
blink_led()
beep()
```

移动到：

```text
alarm_system.c
```

并在：

```text
alarm_system.h
```

中进行声明。

理解了模块化后的程序结构：

```text
main.c
↓
alarm_sys_func()
↓
blink_led() / beep()
↓
led.c / buzzer.c
↓
实际硬件
```

`main.c` 不再负责所有具体控制细节，而只负责调用上层功能。

## 七、三模式报警系统

使用模式变量和 `switch` 实现：

```text
待机模式
→ LED关闭，蜂鸣器关闭

运行模式
→ 正常速度流水灯

报警模式
→ 快速流水灯 + 间隔蜂鸣
```

核心结构：

```c
switch (mode)
{
    case MODE_STANDBY:
        break;

    case MODE_RUN:
        break;

    case MODE_ALARM:
        break;

    default:
        break;
}
```

## 八、static 静态局部变量

使用：

```c
static uint8_t mode = MODE_STANDBY;
```

理解了 `static` 局部变量：

- 只初始化一次；
- 函数结束后仍保留当前值；
- 下一次进入函数时继续使用上一次保存的值。

因此可以实现：

```text
待机 → 运行 → 报警 → 待机 → ...
```

而：

```c
uint8_t led_num;
```

只是当前函数中的临时循环变量，每次进入函数重新使用即可，不需要保存上一次的值。

## 九、STM32 程序运行方式

主程序使用：

```c
while (1)
{
    alarm_sys_func();
}
```

理解了 STM32 单片机程序通常不会像电脑程序一样“运行结束”，而是通过 `while(1)` 持续执行控制任务。

程序使用 F8 烧录到 Flash 后：

```text
断电
→ Flash 中程序仍然保存
→ 再次上电
→ STM32 自动从 main() 开始运行
```

因此断电再上电后程序会重新执行，这是正常现象。
